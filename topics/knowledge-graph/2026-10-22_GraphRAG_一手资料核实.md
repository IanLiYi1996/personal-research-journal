# Microsoft GraphRAG：一手资料核实

核实日期：2026-10-22。范围仅为微软 GraphRAG 及图谱增强检索实践；依据在线文档、官方源码与研究介绍，不推定某个发行版行为。源码与 README 引用固定为当日 main 提交 `c600ff80b77b9b62c47d539a3ac9569e95d8949b`。

## 搜索模式与用途

Local 从问题相关实体出发，组合实体描述、关系、社区报告及原文片段，适合具体人物、对象及局部关联问答，不是单纯沿边遍历。[官方 Local 文档](https://microsoft.github.io/graphrag/query/local_search/)

Global 在选定社区层级的报告上进行 map-reduce：分别生成候选回答，再汇总，适合全库主题、趋势与整体总结；它主要检索社区报告，不等于逐段穷举原文。[官方 Global 文档](https://microsoft.github.io/graphrag/query/global_search/)

DRIFT 结合社区信息与局部检索，先获得较宽背景，再生成追问、细化回答，适合需要跨主题补充语境的问题；这是多步查询，不能假定开销等同 Local。Basic 则是原文 text units 的 top-k 向量检索，是比较基线，而非图遍历。[DRIFT 文档](https://microsoft.github.io/graphrag/query/drift_search/)；[含 Basic 的查询总览](https://microsoft.github.io/graphrag/query/overview/)

## 索引如何组织

原文拆为 text units，抽取实体与关系并汇总描述，用 Leiden 形成分层社区，再由模型生成社区报告。标准路径使用 LLM 抽取；Fast 路径改用 NLP 名词短语抽取和共现关系，因此图的含义及质量并不完全相同。[索引方法](https://microsoft.github.io/graphrag/index/methods/)；[社区结构](https://microsoft.github.io/graphrag/index/outputs/)

输出包括 documents、text_units、entities、relationships、communities、community_reports，常以 Parquet 保存。实体、关系有来源片段标识；社区记录层级、父子社区及成员，报告以 community 关联社区，含摘要、发现、评分和完整内容；不是只有一张“实体—边”表。[输出字段](https://microsoft.github.io/graphrag/index/outputs/)

## 成本与适用边界

成本来自抽取、描述汇总、社区报告、嵌入及查询中的模型调用。官方估计图抽取约占索引成本 75%，是其流程中的经验比例，不是通用报价。Fast 默认 NLP 主要面向英语，也不能直接推定中文效果。[索引方法](https://microsoft.github.io/graphrag/index/methods/)

本文大写 GraphRAG 专指微软的方法和实现，不泛指所有用图辅助检索的系统。依搜索模式定位，不宜以社区报告替代每次精确事实定位。官方要求按数据调优并提醒索引可能昂贵；当前 README 声明主要处于维护状态，且不是微软正式支持的产品。[查询总览](https://microsoft.github.io/graphrag/query/overview/)；[仓库 README](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/README.md)

## 增量更新实际程度

CLI 确有 update 命令。但所核查的默认增量入口按文档 title 集合计算差异，并仅返回 new_inputs：同名正文修改不会成为新增批次；虽然计算 deleted_inputs，入口并未将其交给索引执行。[CLI 命令源码](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/packages/graphrag/graphrag/cli/main.py)；[增量入口源码](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/packages/graphrag/graphrag/index/workflows/load_update_documents.py)；[差异计算源码](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/packages/graphrag/graphrag/index/update/incremental_index.py)

合并会处理实体、关系、描述再汇总及编号映射，但社区与报告采取编号偏移后追加，不能据此宣称全库重聚类。由所读路径推断，不能保证删除传播、同名内容更新、跨新旧子图社区重组，或与全量重建一致；“支持增量”须限定为具体步骤。[实体关系合并](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/packages/graphrag/graphrag/index/workflows/update_entities_relationships.py)；[社区及报告合并](https://github.com/microsoft/graphrag/blob/c600ff80b77b9b62c47d539a3ac9569e95d8949b/packages/graphrag/graphrag/index/update/communities.py)

## 实验观察不能泛化

2024 年官方研究在播客、新闻两个语料上，由 GPT-4 生成问题并用 LLM 裁判比较，观察到全局问题的全面性和多样性优势；这不是所有事实题、所有数据规模或中文任务的胜率。[官方研究介绍](https://www.microsoft.com/en-us/research/blog/graphrag-new-tool-for-complex-data-discovery-now-on-github/)

DRIFT 在 5K+ 篇 AP 新闻、50 个生成的局部问题上，以 LLM 裁判相对 Local 的全面性、多样性胜率分别为 78%、81%；不能写成“回答准确率”或对所有 RAG 的优势。[DRIFT 官方介绍](https://www.microsoft.com/en-us/research/blog/introducing-drift-search-combining-global-and-local-search-methods-to-improve-quality-and-efficiency/)

LazyGraphRAG 延后 LLM 使用，索引无需预先生成社区摘要。官方实验为 5,590 篇 AP 新闻、100 个合成问题（局部/全局各 50），以 LLM 比较全面性、多样性和赋能性；报告索引成本为完整 GraphRAG 的 0.1%，在 100 次相关性测试、低成本模型配置下，全局回答质量相当而查询成本低逾 700 倍，不能泛化为部署预算。[LazyGraphRAG 官方介绍](https://www.microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/)

2025-06-06 编辑说明记录技术已集成 Microsoft Discovery，并随 Azure Local 服务进入公共预览；不应描述成仅停留于论文，也不能据此认定开源库默认提供 LazyGraphRAG。[同页编辑说明](https://www.microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/)
