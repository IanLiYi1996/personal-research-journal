# 部署与查询核实笔记

核实日期：2026-10-23。仅核实模型如何落到持久存储与查询服务；下列配置、Cypher 均为文档示意，未部署、未执行。Neo4j 原生本体管理与 RDF 存储是并列路线。

## 一、Neo4j：原生元模型与实例共同持久化

以下是基于属性图能力的建模建议，不是内置本体 schema：以 `EntityType`、`RelationType`、`PropertyDefinition`、`OntologyVersion` 节点保存类型、关系定义、属性定义及版本；用 `SUBTYPE_OF`、`DOMAIN`、`RANGE`、`HAS_PROPERTY`、`IN_VERSION` 关联。业务节点以 `INSTANCE_OF` 指向类型，或同时使用具体标签。版本节点可保存发布日期、状态、来源、摘要；定义和实例显式关联适用版本，查询显式筛选，不能只记一个“当前版本”便认为历史自动隔离。[Cypher 原生建图](https://neo4j.com/docs/cypher-manual/current/clauses/create/)

`Claim` 独立成节点，分别以 `ABOUT_RELEASE`、`ASSERTS`、`SUPPORTED_BY` 连接 `Release`、`Capability`、`Evidence`；在 Claim 保存平台、版本范围、状态等条件，Evidence 保存来源 URL、定位和采集时间。条件复杂时另设 Condition 节点，由应用解释。不要把有条件、有证据的声明直接压成无条件的“支持”边。

数据库直接执行的是显式创建的标签/关系类型约束：社区版支持属性唯一性；属性存在性、属性类型、键约束属于企业版。唯一性不保证属性存在，类型约束也不保证必填；需另加存在性约束。[官方约束范围](https://neo4j.com/docs/cypher-manual/current/schema/constraints/)、[语法与缺失值边界](https://neo4j.com/docs/cypher-manual/current/schema/constraints/create-constraints/)

```cypher
CREATE CONSTRAINT ov_id IF NOT EXISTS
FOR (v:OntologyVersion) REQUIRE v.id IS UNIQUE;
// 下列两条仅企业版
CREATE CONSTRAINT claim_status_required IF NOT EXISTS
FOR (c:Claim) REQUIRE c.status IS NOT NULL;
CREATE CONSTRAINT claim_status_type IF NOT EXISTS
FOR (c:Claim) REQUIRE c.status IS :: STRING;

MATCH (v:OntologyVersion {id:$version})<-[:IN_VERSION]-(c:Claim)
MATCH (c)-[:ABOUT_RELEASE]->(r:Release {id:$release}),
      (c)-[:ASSERTS]->(k:Capability),
      (c)-[:SUPPORTED_BY]->(e:Evidence)
WHERE c.platform=$platform AND c.status='accepted'
RETURN r.id, k.id, c.id, e.url;
```

此查询只过滤已存字段，并未证明证据可靠或执行版本范围判断。元模型记录不会自动生成约束、检查关系端点、基数、跨版本一致性或条件语义：需应用层校验并控制写入，能表达的规则才转为原生 schema。企业版 Cypher 25 的 `GRAPH TYPE` 可显式声明更强 schema（2026.06+ 正式可用），仍不会自动读取上述元模型节点。[Graph types](https://neo4j.com/docs/cypher-manual/current/schema/graph-types/)

Cypher 的 `SUBTYPE_OF*0..` 可查层级可达性，但不是完整 OWL 推理。APOC 是扩展库，n10s 是 RDF/语义插件；上述原生路线均不需要它们。n10s 的类/属性层级推理不能据此等同完整 OWL 推理。[路径查询](https://neo4j.com/docs/cypher-manual/current/patterns/variable-length-paths/)、[APOC](https://neo4j.com/docs/apoc/current/introduction/)、[n10s 层级推理](https://neo4j.com/labs/neosemantics/4.3/inference/)

## 二、Fuseki＋TDB2：持久 RDF dataset

最小思路是把服务绑定到磁盘 `tdb2:DatasetTDB2`，不是内存 dataset；旧式端点配置仍有效。[TDB2 配置](https://jena.apache.org/documentation/tdb2/tdb2_fuseki.html)

```turtle
@prefix fuseki: <http://jena.apache.org/fuseki#> .
@prefix tdb2: <http://jena.apache.org/2016/tdb#> .
[] a fuseki:Server ; fuseki:services (<#kg>) .
<#kg> a fuseki:Service ;
  fuseki:name "kg" ;
  fuseki:serviceQuery "sparql" ;
  fuseki:serviceUpdate "update" ;
  fuseki:serviceReadWriteGraphStore "data" ;
  fuseki:dataset <#store> .
<#store> a tdb2:DatasetTDB2 ;
  tdb2:location "/var/lib/fuseki/kg" .
```

对应路径为 `/kg/sparql`、`/kg/update`、`/kg/data`（部署上下文路径另计）。向 `/kg/data?graph=urn%3Aontology%3Av1` 发送 Turtle：POST 合并、PUT 替换该 named graph；向不带 graph 参数的 `/kg/data` POST TriG/N-Quads，可按文件内图名导入 quad dataset。查询使用 `GRAPH <urn:ontology:v1>`，不能假定默认图自动包含 named graphs。[Fuseki 端点与 quad 扩展](https://jena.apache.org/documentation/fuseki2/fuseki-config-endpoint)、[Graph Store HTTP](https://www.w3.org/TR/sparql11-http-rdf-update/)

TDB2 存储不自动完整 OWL 推理。推理需另配 `ja:InfModel`、基础图和 reasoner；官方示例包装默认图，不代表所有 named graphs 自动获得同样推理。Jena 内置 OWL 规则引擎也不完备；text indexing 仅可选，不是持久化或 SPARQL 必需。[推理配置示例](https://github.com/apache/jena/blob/main/jena-fuseki2/examples/config-inference-2.ttl)、[推理边界](https://jena.apache.org/documentation/inference/)、[可选全文扩展](https://jena.apache.org/documentation/query/text-query.html)

## 三、Ontop：SQL 上的虚拟访问

OBDA mapping 的 `source` 是 SQL，`target` 是带列占位符的 RDF 模板；也支持 R2RML。配置数据库连接、mapping 和可选 ontology 后，SPARQL 被改写为 SQL，在关系数据库执行；数据仍在 SQL，不必先复制入图数据库。语义支持定位于 RDFS／OWL 2 QL 轻量片段，不应当作任意 OWL DL／Full 推理器，实际查询能力还须核对合规表。[mapping](https://ontop-vkg.org/guide/advanced/mapping-language.html)、[虚拟访问与语义边界](https://ontop-vkg.org/guide/concepts.html)、[查询合规表](https://ontop-vkg.org/guide/compliance.html)
