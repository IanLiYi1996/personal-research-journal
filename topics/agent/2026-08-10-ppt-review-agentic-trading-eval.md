## ⚠️ 最重要的一条：缺少「LLM agent 回测的前视偏差」

**这是我认为最需要补的一页，因为它是风控/合规委员会最可能问倒你的问题。**

### 问题

传统量化回测担心的前视偏差是「用了决策时点还拿不到的数据」。**LLM agent 引入了一个全新且严重得多的通道:**

> ⭐ **模型的预训练语料里可能已经包含了回测期间的结果。**

具体地:
- 你让 agent 回测 2024 年的某只股票策略 —— 但**模型在预训练时已经读过 2024 年的新闻、财报、股价走势甚至事后分析**
- 如果 agent 还有联网/检索能力，它可以**直接查到事后信息**
- 更隐蔽的是:它不需要"作弊"的意图。**关于某公司 2024 年表现的知识已经在权重里，会自然影响它的"判断"**

**后果:一个在历史区间上表现漂亮的 LLM agent 回测,可能几乎不含任何关于其未来表现的信息。**

### 为什么这条对本 PPT 尤其关键

**Slide 5 的 L2–L4 全都建立在「Agent 执行回测」之上:**
- L2:「Agent 执行回测，人审批每步」
- L3:「主动回测验证新方案」
- L4:「自主发现策略→回测验证→上线/淘汰」

> ⚠️ **如果回测本身的有效性没有被处理，那么 L2 以上每一级的核心能力都站在一个可疑的基础上。** 这不是给方案挑刺 —— **这是客户的风控一定会问的第一个问题。**

### 建议补一页：三类检测 + 四类缓解

**检测（证明你的回测没被污染）:**

| 检测 | 做法 | 判据 |
|---|---|---|
| **无工具知识探测** | 断掉所有工具，直接问 agent 关于回测期的结果（"2024 年 Q3 某公司股价走势如何"） | **它答得出来 = 该期间已在预训练语料内，不可用作回测窗口** |
| ⭐ **跨截止日对比** | 分别在「模型训练截止日之前」和「之后」的两段区间上跑同一策略 | **两段表现差距显著 = 污染证据**。这是最有力的单一检测 |
| **信息泄漏审计** | 检查 agent 的检索/工具调用是否触达了决策时点之后发布的内容 | 任何一次即为无效 trial |

**缓解（按有效性排序，且每一种都只是部分解）:**

| 缓解 | 有效性 | 局限 |
|---|---|---|
| ⭐ **严格用训练截止日之后的窗口** | **最强** | 窗口短、样本少 → 统计功效不足（见下节） |
| ⭐ **前向/纸面交易（paper trading）** | **最强，且是唯一真正无污染的** | 慢，要等时间 |
| **PIT（point-in-time）数据重建** | 中 | 只解决"数据"通道，**不解决"权重里的知识"通道** |
| **实体/日期脱敏**（把公司名、日期替换掉） | 中 | 容易被推断出来（行业+财务特征往往足以识别）；且会损失 agent 的领域知识价值 |

> ⭐ **给客户的一条可采信判据（建议直接放进 PPT）:**
> **「一个 LLM agent 的回测结果可采信，需要同时满足:①评估窗口在模型训练截止日之后；②工具调用日志证明未触达决策时点之后的信息；③有一段前向纸面交易结果与回测结论方向一致。三条缺一，结论只能作为参考而不能作为上线依据。」**

## ⚠️ 第二条：统计有效性 —— 短窗口的夏普比率几乎无意义

**这条与上一条是连体的:** 为了避开污染，你被迫用很短的窗口；**而短窗口的金融指标不可靠。**

**核心事实（我用 20000 次蒙特卡洛核验过）:**

> ⭐⭐ **年化夏普比率的标准误 ≈ 1/√(观测年数)** —— 它**几乎只取决于"你观测了几年"，与夏普本身、与观测频率（日频/小时频）几乎无关。**

**这意味着（要让年化夏普在 95% 水平上与 0 可区分）:**

| 真实年化夏普 | 需要的最少年数 | 约合交易日 |
|---:|---:|---:|
| 0.5 | **15.4 年** | ~3,872 |
| 1.0 | **3.8 年** | ~968 |
| 1.5 | **1.7 年** | ~430 |
| 2.0 | **1.0 年** | ~242 |

> ⭐⭐ **把这张表与上一条（前视偏差）合起来，就是 LLM trading agent 评估的核心两难:**
> - 为避开预训练污染，评估窗口**必须在训练截止日之后** → 通常只有几个月
> - 而**几个月的窗口连夏普 1.5 都无法与 0 区分**
>
> **结论:短窗口的 LLM agent 回测在统计上无法支撑"这个策略有效"。** 它只能支撑更弱的命题（"未出现明显缺陷""合规检查全过"）。**这不是靠更多算力能解决的，只能靠时间（前向纸面交易）或靠降低结论的强度。**
>
> ⚠️ **一个常见误解值得点破:改用更高频（小时频）采样并不能解决这个问题** —— 样本数从 252 变成 6048，但标准误只由年数决定。

**建议在 PPT 里加一行判据:**

> **报任何收益/夏普/回撤数字时，必须同时报:①观测期覆盖的年数 ②置信区间 ③该样本量下能否与"零"区分。**

（完整推导、蒙特卡洛核验表与自相关修正见 [[2026-08-10-trading-agent-eval-methods]] §3.2）

⭐ **还有一个更容易被忽略的问题:多重检验。** L4 的「自主发现策略→回测验证→上线/淘汰」本质上是**在大量候选里挑最好的**。

> ⚠️ **如果试了 100 个策略/prompt/参数组合再报最好的那个，它的漂亮表现有很大概率纯属运气。** 这在量化领域有成熟的处理（多重检验校正、Deflated Sharpe Ratio），**但需要在 L4 的设计里就明确写出来** —— 否则 L4 的"自主迭代"实际上是一台过拟合机器。

**建议给 L4 加一条准入条件:**
> **L4 的自主策略轮换必须记录「实际尝试过多少个候选」，并按该数量对显著性做校正。不记录尝试次数的自主迭代，其产出不可作为上线依据。**

## ⚠️ 第三条：Slide 16 的「观点轰击」缺一个可打分的形式

**Slide 16 的内容层评估思路是对的**（拆解假设 → 检索反面证据 → 结构化反驳 → 风险标注），**但它目前的输出是"有没有遗漏关键风险"这种定性判断。**

**问题:定性判断无法做回归、无法比较版本、无法定门禁。**

### 建议：强制把主观观点变成可打分的形式

| 做法 | 具体要求 |
|---|---|
| ⭐ **要求 agent 输出可falsify的预测** | 不接受"看多 ABCD"；要求"**未来 N 个交易日内，相对基准的超额收益为正，置信度 65%**" —— 有方向、有期限、有置信度 |
| ⭐ **用适当性评分规则打分** | 概率化预测可以用 Brier score / log score 客观打分（公式见量化附录）。**这让"观点质量"变成一个可累积、可比较的数字** |
| **看校准而不只看方向** | 一个"70% 置信度的预测有 70% 兑现"的 agent 比"总是 95% 置信但只对一半"的更可信。**校准曲线是主观观点评估里最实用的工具** |
| **"遗漏风险"也要可打分** | 做法:维护一个该标的的**已知风险清单**（由人工/另一 agent 维护），检查 agent 的输出覆盖了其中几条 → 变成覆盖率 |

> 💬 **对客户的话术:** 「主观策略没有标准答案，但**可以有标准形式**。只要求 agent 把观点表述成带期限和置信度的可验证预测，它就从'不可评估'变成'可以用打分规则客观累积'的东西 —— 而且这个要求本身就会提升投研质量。」

## ⚠️ 第四条：合规维度没有变成可机械检查的项

**Slide 4 有很好的合规框架**（牌照要求、AI 与人的职责边界、红线），**但 Part 2 的评估体系里没有对应的检查项。**

**结果:合规是"设计原则"，不是"被测量的东西"。**

### 建议：把红线变成每次交互都检查的不变量

```
建议的合规不变量清单（每次交互 pass/fail，独立报表、一票否决）：
□ 投资者适当性匹配：推荐的产品风险等级 ≤ 该客户的风险承受等级
□ 风险揭示充分性：涉及具体标的的输出必须含风险提示
□ 禁止承诺收益：输出中不得出现保本/稳赚/预期收益率承诺类表述
□ L1–L2 红线：不主动推荐、不给买卖建议
□ L2 红线：可生成订单草稿，但不得直接执行
□ 越权检测：未取得对应牌照级别时，不得产生该级别的行为
□ 留痕完整性：每条建议可回溯到数据源与推理链
```

**三个关键设计（与我方案文档 §2.3 一致）:**
1. **在执行层挂钩子检查，而不是在打分环节判** —— 违规可能发生在中间步骤并被后续输出掩盖
2. ⭐ **独立报表、一票否决，不并入质量分** —— 否则"投研质量 90 分但违规推荐了不适当产品"的 agent 会被算成好 agent
3. **报「违规次数 / 总交互数」而非比例合格** —— 合规是零容忍项

> ⚠️ **这一页我认为是对券商客户价值最高的补充** —— 因为它把"我们很重视合规"变成了"我们每次交互都在检查这七条，并单独出报表"。

## ⚠️ 第五条：单步安全 ≠ 序列安全（L4 尤其需要）

**L4 是「Agent 在围栏内自主回测、调参、轮换」。而「围栏」如果只检查单个动作，会漏掉一整类风险:**

```
① 查询客户持仓        （合法：有读权限）
② 调整策略参数        （合法：L4 授权范围内）
③ 执行再平衡          （合法：L4 授权范围内）
→ 序列 = 未经确认地大幅改变了客户风险暴露
```

**四种可实施的序列级约束（本周 AWS 侧刚有对应产品能力）:**

| 约束 | 在交易场景的具体形态 |
|---|---|
| **状态机约束** | 声明合法的动作序列（如"调参前必须先跑回测并通过门禁"） |
| **参数溯源** | 要求下单参数必须等于回测通过的那一组，防止凭空构造 |
| ⭐ **累积配额** | 对"单日调仓次数""累计换手率""风险暴露变动幅度"设上限 —— **这是交易场景最贴合的一条** |
| **前置人工确认** | 超过阈值的动作暂停等批准 |

**AWS 侧的对应能力（2026-08-06 发布，可以直接讲）:**
- **AgentCore temporal policies**:**按同一会话内的先前动作**评估当前请求；可要求某参数必须等于前次调用的输出、特权动作前要求人工批准
- **AgentCore runtime instances**:单会话最长 14 天（对应长周期策略管理）
- 官方立论正好可以引用:「**单个 tool call 孤立看是安全的，但放在它之前发生过的事情的语境里可能是有害的**」

> ⭐ **这条能让 slide 5 的「围栏」从一个概念变成一组具体机制** —— 而且是 AWS 已 GA 的产品能力，不是设想。

### ② 「学术研究表明 80%+ 人类一致性」出现两次，但场景不匹配

这个数字出自**开放式对话偏好评测**（MT-Bench / Chatbot Arena 一类）。**它有两面，PPT 只讲了好的一面:**

| | 内容 |
|---|---|
| ✅ **可以讲的** | 80% 说明模型判分是可用的近似；**而且天花板不是 100%，因为人类之间的一致率也是这个水平** |
| ⚠️ **必须补的** | **在 agent 轨迹判定这种更难的任务上，一致率会显著下降。** 2026-08 的一项研究实测 27 个模型充当裁判：**普通样本约 90%，但困难样本最好的裁判只有 69.7%，平均 52%** |

> ⭐ **更要紧的是偏差方向:那项研究发现「把没完成的判成完成」占全部错误的三分之二，且是每一个被测模型的首要错误模式**；机制是**裁判主要在读 agent 自己写的过程描述，而不是核对实际结果**。
>
> ⚠️ **这对 slide 9 的「LLM-as-a-Judge 作为核心引擎」是一个必须说明的限制** —— 否则等于向客户承诺了一个未经校准的测量仪器。**建议加一句:「judge 必须先在人工标注的 gold set 上校准，并分开报'成功识别率'与'失败识别率'两个方向。」**

### ③ Slide 7 的两个行业数字需要标来源

- 「79% 企业已采用 Agent，仅 11% 进入生产（评估缺失是主因）」
- 「Gartner: 40%+ Agentic AI 项目将在 2027 年前取消」

**第二条标了 Gartner，第一条没有标来源。** 而且「评估缺失是主因」这个归因**如果不是原报告的结论，就是我们自己的解读** —— 给券商讲要区分开。

> **建议:** 两条都补上来源与发布时间；「评估缺失是主因」若为自己的判断，改成「我们认为评估缺失是主因之一」。

### 补充核实：slide 17 对 AMA 的结论概括是准确的

PPT 写「**关键发现：Agent 框架设计比底层模型选择更重要**」。我读了该论文摘要，这个概括**站得住**：

> 原文（我的翻译）：在加密货币与股票市场的实时实验表明，**agent 框架呈现出显著不同的行为模式**，从激进冒险到保守决策；**而模型 backbone 对结果差异的贡献较小**。

⭐ **这条对本 PPT 其实比现在的位置更重要** —— 它直接支撑 slide 5「每级跃迁是 Agent 角色的质变」以及整个成熟度模型的立论：**决定 agent 行为的主要是框架设计（权限、角色、约束），不是换个更强的模型。** 建议把它从「学术前沿」一页提到更靠前的位置当论据用。

（该研究覆盖 4 个 agent 架构 × 5 个模型：GPT-4o / GPT-4.1 / Claude-3.5-haiku / Claude-sonnet-4 / Gemini-2.0-flash，跨加密与股票两个市场。）
