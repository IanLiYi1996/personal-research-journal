先给 BD 同事建立一个直觉：为什么 agentic payment 是结构性变化，而不是又一个支付方式。

今天所有支付安全机制都假设有一个人在屏幕前——输卡号、收验证码、过 3DS。Agent 在用户不在场的时候自己下单，这套假设就塌了。

BD 一句话：上层协议决定"在哪下单"，下层轨道决定"钱怎么走"——PSP 的价值在于把多种协议接到多条轨道上，并承担合规与风控。

这一页是协议地图，BD 不需要记细节，但要记住"分层"。

最上层是商业编排：UCP 和 ACP，决定 agent 在哪里浏览、下单、结账。第二层是授权和意图：AP2、Mastercard 的 Verifiable Intent，回答"用户到底授权了什么"——注意 AP2 已经由 Google 捐给了 FIDO Alliance。

第三层是 agent 身份：Visa TAP 和 IETF 的 Web Bot Auth，本质都是给 HTTP 请求签名，让商户知道这是一个真实、注册过的 agent。AWS WAF 已经支持 Web Bot Auth 验证。

第四层是执行：x402、Stripe 和 Tempo 的 MPP、卡组织的 agentic token。最底层是钱真正走的轨道。

结论是：没有一个协议包打天下。这恰恰是 Airwallex 这类 PSP 的机会——把多协议接到多轨道上，同时扛合规和风控。我们的机会在于提供它做这件事的基础设施。

这张表是 SA 最常被问到的：AWS 到底原生支持哪些协议。

AgentCore Payments 是这份方案的技术锚点，SA 要把它讲透。

合规页的核心是一个原则：分清楚"可以讲的"和"必须先确认的"。

可以讲的：PCI 相关，Payment Cryptography 有 PCI PIN 和 P2PE 的合规包；美国 GENIUS Act 已经在 2025 年 7 月签署成法。

必须先确认的：DORA 我们核对过原文，集中度风险是第 29 条，退出策略是第 28 条第 8 款——之前流传的"第 30 条、第 12 条"是错的。但 DORA 怎么适用到"AWS 当第二云"上，要由合规团队给口径。MAS 和 HKMA 的具体条款号同样要法务确认。

在支付客户的合规团队面前引错一个条款号，丢掉的是整场对话的可信度。所以监管论据只作为"邀请讨论"，不要当结论讲。

验证中的坑，以及对客户采纳的意义

踩坑记录（SA 上手必看）

坑① WAF 规则必须同时匹配 failed 与 invalid

文档只列 wba:invalid；伪造签名实测返回 wba:failed。只写 invalid，伪造签名会被默认放行。→ 自定义规则需同时包含两个标签条件。

坑② AgentCore Payments 服务角色权限需手动补齐

文档称会自动附加；实测需手动授予 TagResource（workload identity）、GetResourcePaymentToken（凭证提供方）、secretsmanager:GetSecretValue（托管密钥）。

坑③ ProcessPayment 只返回 payload 部分

返回的是 x402 的 payload 字段，不是完整 PaymentPayload；需自行组装 {x402Version:2, resource, accepted, payload} 并 base64 编码。→ 建议直接用 Strands SDK，已封装。

对客户采纳的意义

✅ Airwallex 新账号不依赖 Admin Key

2026-08-24 后注册账号不再发放 Admin Key；状态模拟改用 /simulation/transfers/{id}/transition；发卡用 program.purpose/type，不需要 program ID。客户自助开通沙箱即可完成全部演示动作。

✅ Stripe Privy 无需 Marketplace 订阅

Coinbase CDP 连接器需要 AWS Marketplace 订阅（本账号订阅失败）；Stripe Privy 连接器无需订阅、无需特殊账号权限。唯一前提：用户在会前经 Privy 前端完成钱包授权（约 5 分钟）。

⚠️ 连连 / 通用场景暂定方案

稳定币（真实）+ Nium FX 换汇（真实）+ 本地付款 / 虚拟卡（视开通情况，未开通则走模拟或跳过）。待 Nium 账号团队确认后更新

这一页是踩坑总结和对客户的好消息，各占一半。

三个坑对 SA 上手都很重要。WAF 规则的 failed 条件不是小问题——不加就会漏放伪造签名，这是实测出来的漏洞。AgentCore Payments 权限，文档说会自动加，实测不会，要手动补 TagResource 和 GetResourcePaymentToken，不加会报 AccessDeniedException。ProcessPayment 的 payload 组装，官方文档对这一步写得不够清楚，建议直接用 Strands SDK 内置的 payment tool，已经封装了组装和 base64 编码这些步骤。

对客户采纳意义更大的是右边两个好消息。Airwallex 新账号不需要 Admin Key，之前所有说"需要 Admin Key"的文档都已过时——2026 年 8 月之后注册的新账号只用普通 API Key 就能完整演示，客户零障碍自助体验。Stripe Privy 不需要 Marketplace 订阅，对 SA 在普通 AWS 账号里做 POC 很关键，Coinbase CDP 在我们账号上订阅失败了。
