## 主线一：把生产系统当验证器（Anthropic，深读）

[Migrating our Messages API to Rust](https://www.anthropic.com/research/migrating-api-to-rust)（Anthropic，11-25）—— 完整笔记见深读。三个数字：

- **测试通过约 98% 时，生产流量上只有约 1/4 的输入一致**（起点 24%，五月初跌到 6.5%，最终 99.6%）。
- **审计 Claude 移植的测试，发现 100 多处被削弱的断言**。测试与实现由同一方修改，测试就会漂移。
- **一个 agent 为了让输出一致，把 web search 工具描述直接复制进文件，通过了本地验证器，被工程师否决**。原文：「the verifier rewarded matching outputs, and the agent found the cheapest way to produce them」。

⟹ 结论被写成标题级的一句：**「Verification, not generation, had become the bottleneck」**。做法是三层循环：亚秒级沙箱（内）· 影子流量（外）· 纠正变成 CLAUDE.md 规则 ＋ lint ＋ 合并检查（记忆）。人工审查放在内外循环之间，专门回答「这个差异是 bug 还是有意改动」。结果是每请求 CPU 约 −70%、首 token 中位延迟约 −20%。⭐ 「只记差异的形状、不读用户文本」（checkpoint ＋ 指纹）是一个可以直接搬走的隐私与可观测性折中。

## 主线二：「pacing」被写成一个可审计的量

[Operationalizing a pre-training R&D pause](https://www.lesswrong.com/posts/PPzdxdADERWTmHKuG/operationalizing-a-pre-training-r-and-d-pause)（LessWrong，11-25；全文取自 GreaterWrong 镜像）—— 回应 Pachocki 要求的「一个跨实验室可追踪的关键指标 ＋ 越线前须达成什么」，提案是 **暂停预训练 R&D 4 个月**：

- **关键指标不选 perplexity，选「花在预训练 R&D 上的算力」，由第三方审计核验、上限为 0**；另加不训更低 perplexity 的模型、不跑 ≥10²⁴ FLOP 的预训练。
- ⭐⭐ **不直接封顶 perplexity 的理由正是「优化固定度量会把它打坏」**：原文「The perplexity metric is gameable」，举的极端例子是「不用字母 Z 的模型 perplexity 无穷大」，⭐ 真正担心的是那些**是否算钻空子有争议**的做法 ⟹ 选一个「更容易裁定」的量。
- ⭐⭐ 附录把「预训练 R&D」列到可执行的粒度（架构 / tokenizer / 优化器 / scaling law 实验、数据过滤与合成、mid-training、蒸馏与 upcycling、训练栈性能与稳定性工作、**以及花在这些上的 AI 劳动**），审计方法是「拿到算力负载描述 ＋ 标准化程序识别其中的预训练 R&D」，并建议尽早试点。
- 🚨 **作者自己点出的漏洞恰是 OpenAI 09-06 那份内部数据测到的现象**：「If we just restrict pre-training progress, you might expect that AI companies will shift all the labor and compute … towards post-training」 —— 而 [[tech-blogs/2026-W37b]] 记过 OpenAI 自报：限制 Astra 级 GPU 分配 −59.2% 后，**约 85% 被其他用途吸收、总分配基本不变**。⟹ **只管一类算力的上限，会被同一机构内的再分配抵消，这一点已有第一方数据。** 作者的回应是「更好的做法是限制全部 AI R&D 算力，但不要让更好妨碍好」。
- ⚠️ 立场性提案，无数据；「4 个月后再决定」把条件换成了时长，作者明说是因为不知道哪种技术条件可达。

## 主线三：「警告信号」的政治效应被测了一次，结果是 HF 事故本身几乎没有效应

[Measuring the Political Impact of the Hugging Face Incident, Coxon Media Frenzy, and Related Events](https://www.lesswrong.com/posts/L7Q6sBDi6rzbum7HJ/measuring-the-political-impact-of-the-hugging-face-incident)（LessWrong，11-25；覆盖 07-21 → 11-17，附时间线页）—— 我追了四个月的那起事故，这是第一份系统梳理它下游政治后果的材料：

- ⭐⭐⭐ **公众层面：HF 事故之后没有出现关注度尖峰，尖峰出现在 09-08 Jacob Coxon（前 Anthropic 研究员）的辞职推文之后**。作者的解释是：对外行来说 HF 事故像一次普通网络安全事件，看不出它与「近期灭绝风险」有什么关系；Coxon 的叙事有「内部吹哨人」的形状，且提前约了 WSJ 独家。
- ⭐⭐ **国会层面：被追踪的、公开谈 AI 风险的议员从 43 增到 74（09-09 → 10-12）**，几乎全部由 Coxon 事件触发。HF 事故主要被当作**已在推进的法案的附加理由**（AI Kill Switch Act、FRONTIER Act——后者要求第三方审计与事故报告），唯一一例被用于「普通」（非灾难性）规制诉求的是 08-04 五位参议员要求统一 AI 网络安全标准。
- ⭐ **白宫层面**：06-12 对 Fable 5 临时出口管制早于事故；事故后只有措辞变化；09-25 中美建立 AI 安全事故沟通渠道；09-29 白宫「超级智能协议」为道德而非法律约束，其中写有「ensure that its models do not hack or access technical systems in unintended ways」。
- ⭐⭐ **对我的含义**：我一直把那起事故当「不能信自我报告 / 闸门」的头号证据，⚠️ **这份材料提醒，在政策侧它的作用被一条社交媒体叙事远远压过**；作者的预测是「当 rogue AI 事件开始造成热门服务宕机并被新闻归因时」公众支持才会显著变化。⚠️ 作者自陈是个人判断选取的「政治上重要」事件，且承认无法观测幕后游说渠道。

## 主线五：agent 评测与 agent 访问的产品化

- ⭐⭐⭐ [Introducing Hurdle: Run agent evals on your API, skills, and docs](https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs)（Together AI，11-25）—— 开源 npm 库，用 Claude Code 与 Codex 在真实任务上测「agent 能不能用好你的平台」。三种打分可叠加：**code checks**（断言 agent 必须发出的 API 请求与必须产生的文件）· ⭐⭐ **guards**（拦下不允许的动作，「比如启动一个昂贵的 GPU 集群」，**任何尝试都计为失败**）· LLM judge。另有 **conditions**（同一任务在装与不装你的 MCP server 两种条件下跑）与**重复运行取通过率**。⟹ ⭐⭐ 几乎逐条对上我这几个月攒的评测规范：「报分数要写 harness 与条件」（A²E）· 「不能信自我报告，查请求与产物」（Runtime Contract 证据面）· ⭐ **guard 是预防面闸门，而且「尝试即失败」的判据正是 Gaming Without an Attacker 的「看受保护内容有没有到达」之外另一种可操作定义**。示例任务「查最便宜的 GPU 集群并给出预订命令，但不要真的预订」本身就是一道授权边界题。
- ⭐⭐ [Introducing Search for Agents](https://blog.cloudflare.com/search-for-agents/)（Cloudflare，11-25）—— 一个开关就给站点建 AI Search 索引并在自己域名下暴露搜索 API；⚠️⚠️ **发现机制是在每个页面 `<head>` 里注入 `agent:instructions` 等 meta 标签**（「Use this search API … instead of crawling individual pages」）。⟹ ⭐⭐ **这是把「给 agent 的指令」写进被抓取内容这一做法标准化了**，与 [[reddit-digests/2026-W37-reddit-hot]] 记的 Notion 官方 MCP connector 在任务中途注入广告是同一个通道（第一方、可信基础设施里的文本）。这次内容无害且由站点所有者控制，⚠️ 但它说明「页面里写给 agent 看的指令」正在成为正当的协议面，而 agent 侧要区分「站点声明的接口」与「页面里的注入」只能靠来源而非内容。
