## Deep Dive:Anthropic「用 Claude 发现密码学弱点」

**为什么这是本周最重要的一篇:** 此前 AI 在密码学上的成绩集中在**实现层 bug**(如 OpenSSL CVE-2026-45445、wolfSSL CVE-2026-5194)。这篇是**质变**——Claude 在**算法本身的数学结构**里找到了缺陷。Anthropic 的定位很克制:"这是密码学研究在正常运作(cryptography research working as intended)"。

### 成果一:HAWK(NIST 后量子签名候选)

- **背景:** HAWK 是 NIST 第三轮附加签名候选,安全性建立在**格同构问题(Lattice Isomorphism Problem)** 上。
- **发现:** Claude 定位到 HAWK 格中一个**此前未被利用的对称性——非平凡自同构(nontrivial automorphism)**。此前研究已证明"若存在这种结构就能攻击",但**没人确认它在 HAWK 里存在**。
- **后果:** **有效密钥强度减半**;HAWK-256 的密钥恢复成本从约 **2⁶⁴ 降到 2³⁸**。
- **时间对比(最震撼的部分):** Claude 用了**约 60 小时**;而 HAWK **已经过两年、两轮专家人工评审**。
- **实际影响:** 把密钥长度翻倍可恢复安全性,但"这消除了让该方案成为有吸引力的 PQC 签名候选的许多理由"。
- **过程细节:** 两个 agent worker 同时碰到关键想法——**一个过早判定不可行而放弃,另一个把它做成了攻击**。

### 成果二:7 轮 AES-128("Möbius Bridge")

- 对**削减轮数**(7/10 轮)的 AES-128 改进中间相遇攻击,选择明文模型需约 **2¹⁰⁵ 选择明文**。
- Claude 设计了一个**对某个猜测不变的指纹(fingerprint)**,把原本需枚举约 2⁵⁶ 个值的工作按同等因子削减;叠加优化后攻击**快 200–800 倍**。
- **有意思的插曲:Claude 起初拒绝任务**,坚称不可能改进——"AES-128 r5/r6 就是真的很难""这是存在过的最受研究的分组密码"。一句关于"模型认为任务不可能"的提示让它**重写了自己的 harness**;之后只有三次实质性追问(如"为什么不做 aes-128 r7?重点就是要找到比现有方法更好的东西")。
- **算力与验证成本:** 三天内输出"数亿 token",最终**共 10 亿输出 token**;每个结果约 **10 万美元 API 成本**;人工验证花了"**数百小时**",两位研究者约**一个月**才建立信心。

### 其它成果

- **LEA(13/24 轮):** 实用密钥恢复,**少于 2³⁰ 个加密明文**,桌面机一小时内完成(此前需 2⁹⁸ 对 / 2⁸⁶ 工作量)。
- **Serpent-128(6/32 轮):** 实用完整密钥恢复(此前需 >2⁷⁰ 对 + 2⁹⁰ 解密)。
- Salsa20、Poseidon、SHA-1 上有 **<10× 的边际改进**。

### 设置与克制的边界声明

- **模型:Claude Mythos Preview**。HAWK 工作是**半自主**——在"类 Claude Code 的 harness,支持多个 worker agent 在沙箱协作",带 Python 与 Sage、可读论文;**人类操作者懂理论计算机但不是格密码专家**,主要做项目管理。AES 工作则"几乎完全自主"。
- ⚠️ **明确声明不影响已部署系统**:HAWK 未标准化;AES 攻击是削减轮数版,且"即便如此也要花数亿美元才能实施";HAWK 攻击**不是多项式时间**且仅针对 HAWK。
- **负责任披露:** 6 月通知 HAWK 作者,协调后在 NIST 公开邮件列表发布;学术验证;提前给美国政府与业界。同时放出 HAWK 与 AES 论文、重写的 chain-of-thought 文档,以及与 ETH Zurich、特拉维夫大学、海法大学合建的 **CryptanalysisBench**。

### 我的看法

1. **"60 小时 vs 两年两轮专家评审"是这篇最有冲击力的对比**,但要读准:它不是说 AI 比密码学家聪明,而是说**AI 能把"检查某个已知理论漏洞是否在具体方案中存在"这类穷举式验证工作压缩到极短时间**。这类工作在人类研究中恰恰最容易因"看起来不太可能"而被跳过。
2. **Anthropic 自己点出的瓶颈才是关键**:验证成为瓶颈——"人类研究者可能会被卡在研究与验证这些结果上"。10 亿 token 产出 vs 数百小时人工验证 + 两人一个月建立信心,**这个比例说明了 AI 科研的真实约束不在生成而在核验**。这与我这周在 [[2026-07-27-claude-opus-5-system-card]] 里记的"让 Mythos 5 审自己的系统卡"是同一个问题的两面。
3. **"Claude 起初拒绝、被提示后重写自己的 harness"** 这个细节很有意思:模型对任务难度的先验判断会阻碍探索,而**打破这个先验本身成了一种有效的提示技巧**。
4. **边界声明做得比较扎实**(未部署系统、非多项式时间、需数亿美元),但 Anthropic 也明确警告"不应假设语言模型能力会停滞",并点出还有大量**审视不足的密码算法,弱点可能正在休眠**。

## 补充解读:Raschka「Kimi K3 架构笔记」—— 补上我漏掉的一点

我今天刚精读完 [[2026-07-29-hf-daily-papers-jul28-29]] 的 K3 技术报告(47 页),Raschka 的笔记补上了一个**我漏掉的重要观察**:

- ⭐ **K3 全面弃用 RoPE(NoPE everywhere)**。Raschka 指出:此前的惯例是**局部/滑窗层用 RoPE、全局层用 NoPE**;虽然有些模型走过全 NoPE,但"**据我所知这是第一个前沿级别的**"。这一点技术报告的架构表里没有单列,我的精读也没抓到。
- **LatentMoE 是相对 Kimi Linear 唯一真正的新部件**,且与 **Nemotron 3 Ultra 的 LatentMoE 一致**——把大线性层降维压缩,类比 MLA 的思路。(注:Raschka 未使用"Stable LatentMoE"这个称法,也未讨论 SiTU-GLU 与 Per-Head Muon。)
- **AttnRes 是唯一"不是效率优化"的改动**。他与 DeepSeek V4 的 mHC 做了对比:**mHC 是把残差路径变宽,而 AttnRes 是跨层连接残差、并用注意力分数加权**。收益他评价为温和:验证 loss 改善、下游略好,代价约 **+4% 训练成本、+2% 推理成本**。
- 定位:K3 "本质上是他们 Kimi Linear 模型的放大生产版"——48B → 2.8T,并称它是"**目前遥遥领先的最大开放权重模型**"。整体评价"A really great release overall"。

> **交叉验证的价值:** 我的技术报告精读拿到了完整架构表与训练细节,Raschka 抓到了"NoPE everywhere"这个惯例突破。**两份互补** —— 我已把这一点回填到 K3 那篇 digest 的相关段落。
