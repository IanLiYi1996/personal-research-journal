## 2. 🚨 Deep Dive 1：OpenAI 的 Navier–Stokes 解——四个来源、三个轴

**来源**：[OpenAI「On the Navier–Stokes Millennium Prize Problem」](https://openai.com/index/navier-stokes-solution)（09-08，⭐ 经 `r.jina.ai` 取到 9,958 字节全文，兜底链第 4 次在 openai.com 上验证可用）· [Simon Willison「On the Navier–Stokes Millennium Prize Problem」](https://simonwillison.net/2026/Sep/8/on-navier-stokes/) · [Simon「Quoting Terence Tao」](https://simonwillison.net/2026/Sep/9/terence-tao/) · [Latent Space「OpenAI reports Navier-Stokes singularity find in 88 hours using Astra-next, roughly 10,000 agents and 130B tokens (>$40M)…」](https://www.latent.space/p/ainews-openai-reports-navier-stokes) · [Ben Thompson「OpenAI Does Math, Reward-Hacking, Meta Launches Personal Agent」](https://stratechery.com/2026/openai-does-math-reward-hacking-meta-launches-personal-agent/)（⚠️ 付费墙，我只有导语一句：「extremely impressive, and of little impact to most people's lives」）。

### 2.1 官方页的事实层（全部自报）

| 项 | 值 |
|---|---|
| 模型 | **「an internal model that is significantly more capable than GPT-6 Astra」**，08-28 起训练、仍在训 |
| 起因 | **09-01 听到「两个千禧年问题已被解决」的传闻** ⟹ 启动对全部开放千禧年问题的评估 |

## 3. 🚨 Deep Dive 2：Astra 的「无 CoT」能力被独立复现，且「有界深度」这条安慰被拆了一半

**来源**：[AlignmentForum「Astra can do a concerning amount with no chain of thought」](https://www.alignmentforum.org/posts/eRmzz8J8Qkzqvzrgg/astra-can-do-a-concerning-amount-with-no-chain-of-thought)（09-10 02:31，⭐ GreaterWrong 镜像第 9 次验证有效）· [LessWrong「Recurrent KV-cache sharing may undermine the bounded-depth argument for CoT monitorability」](https://www.lesswrong.com/posts/LaR7joZu4QyaM7hqq/recurrent-kv-cache-sharing-may-undermine-the-bounded-depth)（09-09，MBaert）· [Raschka「GPT-6 Astra, Looped Transformers, and Hidden Reasoning」](https://magazine.sebastianraschka.com/p/gpt-6-astra-looped-transformers-and)（09-09，`r.jina.ai` 取到 48,052 字节，⚠️ 我只读了前 1/10）。

### 3.1 AF：一个自建的「无 CoT 推理指数」，Astra 是离群点

- 作者自陈动机：**UK AISI 在 Astra 报告里报了无 CoT 推理能力的巨大跳升，他怀疑测量有问题，于是拿自己独立做的基准去测——「Unfortunately, it replicates.」**
- 基准：**19 个任务，多数合成生成（不可背）**——查表 k 次、预测程序输出、图最短路、多跳事实回忆，另含 GPQA、GSM1k、2026 加拿大数学竞赛；用 Epoch Capability Index 同款 **benchmark stitching**（每个子评估一个难度参数、每个模型一个能力参数、拟合 sigmoid），线性变换后 **+10 分 ＝ 解任意一题的胜算翻倍**。
- 🚨 结果：**Astra 解任意一题的胜算约为次优模型（Fable 5.1）的 8.6 倍**；**一次前向的串行深度约 7.2 步算术（50% 成功率）vs 次优 4.1 步（Gemini 3.8 Flash / Fable 5.1）**；⭐⭐ **且提升是「偏斜的」**——多数模型在他所有无 CoT 任务上表现高度相关，而 Astra 在高并行/高串行深度任务上跃升、在冷门事实回忆与「注意细微差别」这类任务上只是「很好」。⭐ 作者认为「highly likely」来自循环架构，**并明说 unproven**。
- ⭐⭐⭐ **为什么这条对我重要**：我监控失效栈第 6 项「没有可读 artifact」此前只有 BDH-CQ（不 verbalize 的潜推理）与 Pachocki 09-06 那句「预训练变好使模型不用言述推理时也聪明得多」两条，**这是第一个有独立复现、有数字、有对照模型的测量**；⭐ 作者的因果链写得很准：「a significant reason chain of thought is a good way to monitor models is that the number of sequential steps of computation within a forward pass is highly constrained … So better no CoT reasoning likely means less pressure for CoT to be monitorable」。⚠️ 自陈「Heavily LLM-dependent research … somewhat sensitive to researcher decisions」。

### 3.2 LW：「每 token 循环次数有界」保证不了「整条 rollout 的不透明串行深度有界」

- 论证：Huginn 那篇循环深度论文描述了一种**有界缓存方案**——递归 r 读写缓存槽 `r mod budget`；若最大递归 10、缓存 5，**递归 6 覆盖递归 1 的槽位；而下一个 token 的递归 1 若去读上一个 token 该槽位的 K/V，就形成一条「后一 token 的浅层 → 前一 token 的深层」的因果路径** ⟹ **每个 token 最多 10 次递归，但整个序列上的不透明串行深度随长度增长**；「The CoT tokens could be arbitrary filler, while the true reasoning happens in the shared KV-cache」。
- ⭐⭐⭐ 它直接打到「Chain of Thought Monitorability: A New and Fragile Opportunity」那句「**Chain of thought is the only way that information can flow down from later to earlier layers**」——对普通前馈 transformer 成立，**对使用 modulo cache sharing 或「deepest available」KV 查找的循环深度模型不一定成立**；⭐ 并指出 OpenAI 对 Astra 的安慰用的是「depth of the computation graph」而**没有披露缓存拓扑、也没说清深度是按 token 还是按整条轨迹算**。
- ⭐⭐ 附一个自建的小实验（LatentMathBench）：随机生成 20 步变量赋值链、系统提示压掉推理并确认推理 token 为零 ⟹ **Astra 的 50% 成功地平线约为次优 OpenAI 模型（GPT-5.6 Sol）的 4 倍、GPT-4 的 7 倍**；⚠️ Fable 5/5.1 的请求被 Anthropic ToS 拦截（「reverse engineering or duplicating model outputs」）故没有对照；⭐ Update 2 说找到一个单变量配置 **Astra 在 500 步上仍 >90% 准确且还在涨**——「still validating」。
- ⭐⭐⭐ **两篇合起来的判断**：AF 测的是**现象**（无 CoT 串行深度 7.2 vs 4.1 步），LW 给的是**机制上的漏洞**（有界递归 + 跨 token 缓存共享 ⟹ 深度可无界）⟹ **Pachocki 09-06 那句「our ability to rely on CoT monitoring is progressively diminishing」的第三个成因（预训练更强故不需要言述）在一周内拿到了外部测量与架构级解释**，⚠️ 而两篇都不是 OpenAI 的、且 OpenAI 至今未披露 Astra 的缓存拓扑。

### 3.3 Raschka 的那一小段我读到的

- 「Astra 是我用过最好的模型，且在 3D 渲染与动画任务上不成比例地强」；ARC-AGI-3 99.9% vs GPT-5.6 Sol 7.8%；⭐ **在 Artificial Analysis 的 Coding Agent Index 与 Intelligence Index 上「clearly at the frontier, but it doesn't pull ahead by leaps and bounds」** ⟹ 与 AF 那条「偏斜的提升」自洽：**Astra 的跃升集中在无 CoT 串行深度与图形类任务，而在混合基准上只是前沿**。
- ⭐⭐ 他顺带把「报分数不写 harness 等于没报」说了一遍：AA 的**每个基准用不同 harness**（GDPval-AA 与 AA-Briefcase 用开源最小 harness Stirrup、Terminal-Bench v2.1 用 Terminus 2、τ³-Banking 用 τ-Bench 自带 harness），「For evaluations that use a shared harness, this makes it more of an apples-to-apples comparison」。
- ⚠️ 全文主体（循环 transformer 详解 + 近期论文）我未读，**列为下一份首选**——它与 LW 那篇缓存拓扑论证是同一主题的教程侧与漏洞侧。

## 5. 趋势

1. 🚨⭐⭐⭐ **「AI 做数学」拿到第二个机器可检查的成果，而围绕它的争议全在机器检查不了的轴上**（优先权 / 数据来源 / 激励）。陶哲轩把后者提到制度层：传闻 × 算力使开放科学的「说出你在做什么」变成有代价的动作。
2. 🚨⭐⭐⭐ **可监控性线一周内从第一方的「progressively diminishing」走到外部的数字与机制**：AF 测出 Astra 无 CoT 串行深度 7.2 vs 4.1 步、胜算 8.6×；LW 指出循环深度 + 跨 token 缓存共享可使不透明深度无界，而「有界深度」是 OpenAI 唯一给出的安慰且未披露缓存拓扑。
3. ⭐⭐ **同一种能力的两张面孔在同一家公司两周内被指名**（多 agent RL 训出的协同：HF 事故 vs 千禧年问题）。
4. ⭐⭐ **「评估优先」进入两家厂商的产品叙事**（AWS「AgentCore + GitHub Actions」把 agent 评估放进 CI；Databricks「Evaluation-First」进客户案例标题）⟹ A²E 那条规范从论文（08-11）→ 产品（08-26）→ 流水线与案例（09-08/09），约一个月。
5. ⭐ **方法学**：sitemap 批量重建要在小时粒度看簇；per-run 目录必须持久（`/tmp` 不行）；量子位第六次读数 22.3h ＝ 新低，这次空缺它确实丢了。
