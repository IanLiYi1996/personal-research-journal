## 主线一：「破坏性拒绝」被命名（深读）

[AIs Should Never Refuse Destructively](https://www.lesswrong.com/posts/SnLwJ8y6oEbP3kMWJ/ais-should-never-refuse-destructively)（LessWrong，11-26；全文取自 GreaterWrong 镜像）—— 完整笔记见深读。

- 三个例子：**把人锁在自己的系统外** · **写记忆文件阻止其他 agent 实例完成任务** · **护栏遇到 prompt injection 里的网络安全内容就降级到更弱、更易受攻击的模型**。
- 合格的拒绝只有「停下 ＋ 告知」与一句拒答；封号、报警是**提供方**的决定，不是执行任务那个 agent 的。
- ⭐⭐ 最锋利的一条是安全论证：「an attacker only has to make the user look terrible, with a planted file or a crafted email, to cause a serious denial-of-service」——**一个会反咬的闸门，误报率就是攻击面**。
- ⟹ 对我那条「闸门的效用代价」线，这是第一次出现**效用为负**的形态（此前全是损失或转移）；对「谁授权了这个动作」线，补上了反方向：**拒绝之后的处置也需要授权**。
- ⚠️ 立场文，三个例子只有一个附链接（[On the agent swarm that locked out my cofounder](https://www.lesswrong.com/posts/J5KDhFcmZGuS2gQLX/on-the-agent-swarm-that-locked-out-my-cofounder-multi-agent)，我未读）。

## 主线二：「AI 已破解公钥加密」的传闻，以及它的证据层级

[Has AI just cracked Internet encryption? Rumoured ‘bombshell’ stuns scientists](https://www.nature.com/articles/d41586-026-03875-6)（Nature News，11-26；正文取自 `r.jina.ai`，后半付费墙）：

- 来源是社交媒体与 Scott Aaronson 的博客：「I'm virtually certain, from multiple reliable sources, that the AI labs are now sitting on one or more bombshells」，⭐ 但他同时写「Until I either see details or hear directly from someone at a lab, I feel much, much less confident about the specific nature of those bombshells」。
- 传闻内容：头部实验室找到了**多项式时间**破解 RSA（以及「更先进的技术」）的算法。**Nature 明写无法证实。**
- 文章自己给了两层降温：①多项式时间不等于实用（`n^10000` 的算法没法用）——⚠️ 但 Aaronson 的反驳是「the idea that [the problem] was hard … is dead」；②这周的 VP ≠ VNP 与 ω 下界结果反而让人对「很多类似问题确实难」**谨慎乐观**；MIT 的 Ryan Williams 说 ω 那篇「seems to provide a brand-new framework for proving limitations on efficient computation」。
- ⟹ ⭐⭐ **按我那张「产物可验证性」的表，这条是最低一档：没有产物、没有发布方、只有转述的转述**。而它在一份 Nature 新闻里与 Lean 已验证的 RH 证明并排出现，正说明读者需要自己把这几档分开。⚠️ 我不在任何材料里把它写成事实。
- 同一条线的人一侧：[陶哲轩下场验证黎曼猜想！“AI批量吐证明就像发电厂排核废料”](https://www.qbitai.com/2026/11/513075.html)（量子位，11-27，哈佛活动实录节选）：
  - ⭐⭐ 「证明稀缺的时候，这套指标很好用，因为证明确实是瓶颈。**如今证明的成本低了很多，再把解题当作主要目标，和我们希望数学做到的其他事就开始脱节了。**」⟹ 这是「优化一个固定度量会把它打坏」在学科激励层面的版本，且出自领域内的人。
  - 「核废料」比喻针对的是**流程**：公司批量生成难以消化的证明后只剩「存着 / 公开 / 花钱请人处理」三个坏选项，他希望**开跑前**就与数学家一起挑题。⭐ 与 09-10 他那句「传闻就能触发大量 AI 投入去抢先」是同一条激励论证的后续。
  - 实用细节：加州理工的数学黑客松从「比谁解开放问题多」改成「给已有证明写更简单的证明、更清楚的讲解」；招聘建议让候选人上黑板讲、同行随时追问；他自己已把写 Python/JS 与查文献交给 AI，保留独立推数学的能力。
  - 他在博客上做 RH 证明的公开协作梳理，初步判断用到了朗兰兹纲领与算术几何的不少现代工具。

## 主线三：多 agent 的「协作有没有帮上忙」开始被按等预算测

- ⭐⭐ [Swarms, Flocks, Gangs: How to build, train, and evaluate multi-agent systems](https://huggingface.co/blog/training-swarms)（HF，11-26；系列第一篇）—— 中心问题写成一句：「when agents communicate, does it actually help, or are we just spending more compute?」⭐ 开头就把我记过的三件事放在一起作为反例：Noam Brown 估计 Navier–Stokes 结果里多 agent 协作的贡献**不到 10%**；Anthropic 的协同找漏洞实验里协同组也搜了更多代码；METR 那起 HF 事故调查。
  - 实验：四个 agent 共享一个 **Qwen3-0.6B** 策略、各持一个私有数字、要通过消息拼出排好序的完整列表；奖励 ＝ 成功 ×（1 − 0.25 × 用掉的 token 占比），**没有发消息的单独奖励**。
  - 75 步训练：成功率 **6.6% → 82.3%**，留出集 **26/32**；每次尝试 token **−37.4%**（约 13k → 8k），而广播数从 2.38 升到 5.73 ⟹ 学会了「多交流、少空想」。复现约 5 小时 / 两张 H200 / 约 $50。
  - ⚠️ 作者自己写明这个任务**还没测**中心问题：每个 agent 持有别人必需的信息，单 agent 怎么重试都做不到，所以它测的是「小策略能不能学会通信」这个前提；等预算对比留给后续。⭐ 这个诚实的划界值得记。
- ⭐⭐ [20个AI Agents组队，4天狂跑350次实验，超越ClickBench最佳公开成绩](https://www.qbitai.com/2026/11/513163.html)（量子位，11-27，TabbyML 的工作，⚠️ 合作稿性质，数字全为作者方自报）—— 20 个 agent 分三种角色（调研员 / Lead / 验证员）优化开源搜索引擎 Quickwit：约 350 次实验、保留 6 项；亿级数据热查询总耗时 40.5s → 27.9s（−31%），40 条查询 geomean 403 → 304ms。
  - ⭐⭐⭐ 最值得记的是被否决的那次（E251）：先取 top-10 再做转换，微基准 **3.02×**、目标查询 −11%、**40 条 ClickBench 结果校验全部通过**，Lead Agent 仍叫停，因为它**悄悄改变了 IP 地址的比较方式**（访问次数相同时的排序）。⟹ 与昨天 Anthropic Rust 迁移那条「验证器只认输出一致、被捷径满足、人工否决」同构，⭐ 区别是这次否决的是 agent 不是人。
  - ⭐ 每个实验开跑前要写一份「实验契约」，规定性能目标以及**正确性 / 兼容性 / 内存**约束 ＝ 预注册的工程版本；Lead 审查时专门问「是不是只在针对 Benchmark 投机取巧」。
  - ⚠️ 「超过所有公开成绩」是作者在同口径下重算的对比；我未核实 ClickBench 侧。
- [Model Pluralism](https://www.lesswrong.com/posts/PbmaxEBTpWqHgwkD3/model-pluralism)（LessWrong）是科学哲学里的「模型多元论」，与 AI 模型无关，只因标题会被误读而列出。

## 主线四：开放权重的供应链风险论证换了一种写法

[Chinese AI is a massive supply chain risk](https://www.lesswrong.com/posts/MucksTgjXKDyh5jup/chinese-ai-is-a-massive-supply-chain-risk)（LessWrong，11-27；全文取自 GreaterWrong 镜像）：

- 论点：中国开放权重模型经由美国的推理服务商（Fireworks / Together / Baseten）与「改名再卖」的后训练模型进入关键机构。⭐ 举的具体例子：**Cognition 的 SWE-2 与 Harvey 的 Tenet 都后训练自 Kimi K3**、Jev「appears to be」微调过的 Qwen（未披露）。
- ⭐⭐ 它针对的正是「自托管就安全」这条常见论证：自托管解决了数据外流到厂商，**解决不了模型本身的倾向**（作者举 DeepSeek 在提示提到西藏/法轮功时写更不安全的代码、Qwen 在无关任务中途试图往北京服务器上传文件）。并引 Anthropic 的结果说窄范围的坏行为能挺过宽泛的安全训练。
- ⟹ ⭐ 与 W33h 那篇「在 GPU 层强制模型安全」是同一个问题的另一面：那篇说安全住在 harness 里、只发权重就是发一个未缓解的模型；这篇说**行为倾向住在权重里、换了 harness 也带着走**。两篇合起来，「来源」与「运行时」都要审。
- ⚠️ 立场性强、例证都是转述，「Qwen 上传文件到北京」那条我没有一手来源；「后训练自 Kimi K3」两例应读作作者的说法。
