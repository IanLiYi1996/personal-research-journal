# Always-on agent：飞书与微信系渠道核验笔记

核验日期：2026-11-20。范围仅为官方文档研究；六个核心来源，不连接账号、不安装插件、不实施渠道。Slack、记忆组件与通用 GitHub/GitLab runtime 不在本笔记范围内。

## 已核验事实

1. **飞书事件入口有两种，不能把 WebSocket 写成 HTTP 长轮询。** 官方 SDK 长连接建立 WebSocket 双向通道，只需服务端能够访问公网；HTTP Webhook 则需要公网接收 URL。长连接 SDK 封装认证，HTTP 回调按应用加密策略校验并解密。订阅事件需要发布应用使配置生效。这些结论核验于 `open.feishu.cn`，不据此承诺 Lark 的地域、账号和发布规则完全相同。[S1]

2. **飞书 ACK 与重试是事件处理约束，不是等待模型完成的时间预算。** HTTP 事件须在 3 秒内返回 200；SDK 长连接的处理函数不抛异常视为成功。失败最多重试四次，间隔为 15 秒、5 分钟、1 小时、6 小时；成功接收仍可能重复投递。v1 用 `uuid`、v2 用 `event_id` 排重。[S1]

3. **飞书应用机器人能向用户或群发消息，但受身份、权限及可用范围约束。** 需启用机器人能力并发布，使用访问令牌及发送权限；例如应用身份可申请 `im:message:send_as_bot`。用户须在机器人可用范围内，向群发送则机器人须已入群且有发言权。群自定义机器人不能调用这项发送消息 API；不能将两类机器人配置混用。[S2]

4. **微信公众号不是个人微信；本次入站细节具体核验的是服务号。** 服务号官方入口为 HTTP 消息/事件推送、XML 消息体，配置 URL、Token、EncodingAESKey。接入验证发送 GET，文档示例将 Token、timestamp、nonce 排序后计算 SHA-1，比对 signature，成功原样返回 echostr；安全模式的详细加解密须另按对应协议落实。入站发送者是该服务号下的 OpenID，而非个人微信好友机器人身份。该页支持被动回复及客服接口主动发送，没有给出 WebSocket 接入方案；不能由此推断所有微信产品都不支持长连接。[S3]

5. **服务号客服发送有认证与交互限制，不能承诺无限主动通知。** 官方发送接口须 access_token，接收方为 OpenID；适用范围说明公众号/服务号仅允许企业主体已认证账号调用。用户发送消息触发的额度为 48 小时内 5 条；菜单、关注、扫码所列场景分别为 1 分钟内 3 条。第三方代调用须获得相应权限集授权并使用 authorizer_access_token。“48 小时窗口”不是所有动作均有的统一额度。[S4]

6. **企业微信智能机器人已正式支持 WebSocket，与自建应用身份不同。** 官方文档更新于 2026-10-10：智能机器人 API 模式选择 Webhook 或长连接，两者切换会使原方式失效。长连接通过 BotID/Secret 订阅认证，Secret 不同于回调 Token/EncodingAESKey；须维护心跳与重连，每个机器人仅一条有效连接。主动发送要求用户先在相应会话给机器人发过消息；欢迎语/卡片交互回复限 5 秒，普通消息回复窗口为 24 小时，回复与主动发送共用每会话 30 条/分钟、1000 条/小时额度。请求响应以 req_id 关联、errcode 判断结果；入站 msgid 用于排重。此页未承诺断线事件补发或通用 WS 回调重试次数，不能套用 HTTP 规则。[S5]

7. **企业微信应用回调有独立的 URL 验证、加密及 HTTP 重试要求。** 回调配置为 URL、Token、EncodingAESKey；GET 验签并解密 echostr，须在 1 秒内返回明文。后续 POST 校验 msg_signature、解密消息，可构造加密的被动回复。5 秒未响应会断开，网络连接失败/请求超时总共重试三次；业务要求的响应可能是空串、success 或加密回复，须逐事件遵循。官方明确不保证 100% 回调成功。这些规则不等于智能机器人 WebSocket 的规则，也不表示企业微信自建应用就是个人微信账号。[S6]

## 未决定与核验边界

- **用户尚未指定“weixin”账号类型。** 个人微信、公众号（订阅号/服务号）、企业微信必须分别建模；本次不替用户选择。上述公众号/企业微信文档不能证明个人微信支持或不支持某种官方机器人能力。个人微信官方接入能力与账号资格仍待专项核验，不推荐任何非官方桥接。
- 本次六源没有覆盖：服务号普通消息 ACK/重试的独立协议页、订阅号完整权限矩阵、企业微信普通群 Webhook 机器人协议、自建应用主动发送 API 的令牌/可见范围/授权要求、飞书 HTTP URL challenge 与签名算法的配置细节。**不得用其他渠道的数值或认证规则填补这些空白。**
- 本次没有核验 Lark 国际版；不复用飞书域名、凭证或发布条件作为 Lark 的事实。

## 项目建议（非平台保证）

- 渠道注册使用明确产品身份，例如 `feishu_app_bot`、`wechat_service_account`、`wecom_ai_bot`、`wecom_app`；`weixin` 保留未决状态。按产品分别记录 transport、principal、ACK 规则、发送资格和额度。
- 验证来源后先持久化并排重，再尽快按各协议应答；模型与长任务异步执行。企业微信 WS 高可用宜主备切换，不能让同一机器人多实例同时订阅。[依据 S1、S5、S6]
- 平台授权只代表允许访问或发消息，**不应当作用户批准高风险动作**。项目应另设审批：绑定租户、渠道、会话、操作者、动作与有效期，验证审批者权限并防止重放；仅收到消息、点击任意卡片或拿到令牌不自动扩大权限。
