## 0. 为什么把这三篇放在一起

**因为它们合起来是一条完整的、少见的论证弧 —— 同一个人先把「softmax 能不能被线性注意力替代」这件事推到底，然后解释自己团队出货时为什么没有那么做。**

```
①  softmax 的一阶展开  ─────────────►  得到 Vanilla Linear Attention（最弱的那档）
②  换个推法（对角元近似 + 替代 q）──►  直接得到 Gated DeltaNet（相当强的那档）
    ⭐ 而且发现：softmax attention 的精确递归本身就长着 Delta Rule 的样子
─────────────────────────────────────────────────────────────────
②(评论区) ⚠️ 但两者不可严格互换 ──►  delta rule 能做 state tracking，softmax 不能
③  K3 实际出货  ─────────────────►  KDA（线性）+ MLA（softmax）混合，两个都留着
    ⭐ 并给出「比 MLA 更好的 Attention」必须同时满足的四个条件，以及为什么目前无解
```

> ⭐⭐⭐ **一句话总结这个专题:线性注意力在数学上可以逼近 softmax，甚至能从 softmax 里「推出来」；但逼近是单向且有损的，两侧各有对方做不到的事，所以工程上的答案是混合而不是替代。**

## 1. ① 数学工具：softmax 的泰勒展开

**出发点是一篇论文** —— [The Key to Going Linear: Analysis-Driven Transformer Linearization](https://arxiv.org/abs/2607.07706)（arXiv:2607.07706），它直接对 softmax 做近似展开来线性化 attention。苏剑林把这套展开重做了一遍并整理清楚。

**关键技巧只有两步:**

1. **用均值做中心化**：记 `y = x − x̄`，则
   `logsumexp(x) = log n + x̄ + ȳ²/2 + ȳ³/6 + (ȳ⁴/24 − (ȳ²)²/8) + ⋯`
   （最后一步用 `log(1+t) = t − t²/2 + t³/3 − ⋯`）
   > ⭐ **引入 x̄ 的偏置纯粹是简化技巧** —— 不引入也能得到等价结果，只是要把 y 的各项显式展开成 x 的矩，形式难看得多。
2. **用恒等式 `softmax(x) = ∇ₓ logsumexp(x)` 直接对上式求导**，得到
   `softmax(x) = (1/n)·(1 + y + (y²/2 − ȳ²/2) + (y³/6 − ȳ³/6 − ȳ²y/2) + ⋯)`

**⚠️ 一个他明确指出的陷阱，我认为值得单独记:**
> **截断有限项后，右端各分量之和仍然为 1，但无法保证每个分量非负。** 「这一点在实际应用中需要留意（比如需要取对数求熵的时候）。」

> ⭐ **这条对做评估的人是有用的警告:一个「看起来是概率分布」的近似（和为 1）可能含负分量，任何需要 log 的下游计算（熵、KL、log score）都会炸。** 与我在评估文档里用 log score 给概率预测打分那条正好相关 —— **近似出来的分布不能直接喂进对数型评分规则。**

**这一篇的结局是「够用但不够好」:** 只取一阶，代进 attention 就得到
`o_t ≈ v̄_t + ( (1/t)Σ vᵢkᵢᵀ − v̄_t k̄_tᵀ ) q`
—— **这是最早的 Vanilla Linear Attention（VaLA）的变体**，而 VaLA 是线性注意力里最弱的一档。

## 2. ② 推导：一路推到 Gated DeltaNet

**这一篇是三篇里数学最漂亮的。它的目标是：能不能直接把 softmax 线性化成比 VaLA 更强的 DeltaNet / GDN？**

### 2.1 ⭐⭐ 先有一个「无需近似」的发现

把 softmax attention 写成 RNN（固定 q）：

`o_t = (Z_{t−1} o_{t−1} + e^{q·k_t} v_t) / Z_t`  ⟹  **`o_t = o_{t−1} + α_{t,t}(v_t − o_{t−1})`**

> ⭐⭐⭐ **右端的增量是 `v_t − o_{t−1}`，即「新观测与旧预测之差」—— 这已经是 Delta Rule 的形状。而这一步完全精确，没有做任何近似。**
> **他的推论:「这暗示了 Softmax Attention 与 Delta Rule 存在一些天然关联。」**

**同时这也解释了「softmax attention 是平方复杂度的 RNN」的确切含义:** 上式是**固定 q** 的递归，而实际每个位置有不同的 q₁…q_t，每个 q 都要独立跑一遍 1,2,…,t 步，总复杂度 `1+2+⋯+t = O(t²)`。
> ⭐ **由此线性化的目标被精确地表述出来:把 q 的运算分离出去，让迭代只在 k, v 内进行，再用迭代得到的状态与 q 做输出运算。** 迭代不依赖 q ⟹ 只需迭代一次 ⟹ 线性。

### 2.2 ⭐⭐ 两个我认为很值得学的技术判断

**（a）只近似对角元，近似负担大大降低。**
他对 `α_{t,t}` 用一阶近似。读者自然会问：刚才不是嫌一阶近似不准吗？
> **区别在于:之前需要对全体 (t,i) 对的 `α_{t,i}` 做近似，现在只需近似 `α_{t,t}`，也就是只近似对角线。近似负担大大减少，精度随之增加。**

**（b）⭐⭐⭐ 而更漂亮的是他给出的第二个视角 —— 为什么分解后再近似严格更好:**

`α_{t,i} = α_{i,i}(1 − α_{i+1,i+1})⋯(1 − α_{t,t})`

> 「直接对 `α_{t,i}` 做一阶近似，跟分别对 `α_{i,i}` 和 `α_{j,j}` 近似，相当于 **`e^{a+b} ≈ 1+a+b`** 和 **`e^a e^b ≈ (1+a)(1+b) = 1+a+b+ab`** 的区别，**后者能引入交叉项，实现更高的精度。**」

> ⭐⭐ **这是一个可以搬到别处用的一般性洞察:把一个量先按结构分解、再对每个因子做低阶近似，会自动保留因子之间的交叉项，因此优于对整体做同阶近似。** 我认为这条比本文的具体结论更通用。

### 2.3 关键一步：给残余的 q 找替代品

做完对角近似，递归仍是平方级的 —— 因为 `o_{t−1}` 里还含 q。于是他寻找形如 `o_t ≈ A_t q + b_t`（A_t, b_t 与 q 无关）的解，代回递归后残留一个误差项，需要给里面的 q 指定一个不依赖 q 的替代 c。

**⭐ 他的「最小误差原则」是一个极小极大策略:**
> 误差项是**相乘**的形式：若 `α_{t,t}(q)` 本来就小，乘起来也不会大；若 `α_{t,t}(q)` 很大，则 `o_{t−1}(q) − o_{t−1}(c)` 必须小。
> **于是：先找让 `α_{t,t}(q)` 最大的 `q*`，再取 `c = q*` 使该处误差为零** —— 这样平衡了大 α 与小 α 两侧的误差。

由一阶近似 `α_{t,t} ≈ (1/t)(1 + q·(k_t − k̄_t))`，最大化方向是 `(k_t − k̄_t)/‖k_t − k̄_t‖`；因模长可任意大而无最大值，故**假设 q 与 k 的模长相当**，直接取

**`q* = k_t − k̄_t`**

代入后得到

`A_t = A_{t−1}( (1 − 1/t)I − (1/t)(k_t − k̄_t)(k_t − k̄_t)ᵀ ) + (1/t)(v_t − v̄_{t−1})(k_t − k̄_t)ᵀ`

**⭐ 而 GDN 的标准形式是** `S_t = S_{t−1}( α_t(I − β_t k_t k_tᵀ) ) + β_t v_t k_tᵀ` —— **形状一致。**

> ⭐⭐ **所以结论是:从 softmax attention 出发，经「精确递归 → 对角元一阶近似 → 极小极大选替代 q」三步，得到的不是基本 DeltaNet 而是直接得到 Gated DeltaNet。** 苏剑林自己用的词是「令人意外」。
> ⚠️ **注意其中一处是明确的假设而非推导:「q, k 模长相当」。** 评论区有人追问 `‖k_t − k̄_t‖ = ‖k_t‖` 凭什么成立，他回答**「『相当』不是『相等』，这里只是一个概述，试图简要解释直接取 q* = k_t − k̄_t 的合理性」** —— **即这一步是启发式的。**

## 3. ⚠️⚠️ 但「等价」不成立 —— 两条限制都出自他自己

**这是我认为这个专题最关键的一节，而它的内容不在正文里，在②的评论区回复中。**

### 3.1 推导给出的是「形式」，不是「学到的参数」

有读者指出：按这个推导，α 和 β 等价于「时间步单调递增带来的平均」，所以应当互补且随 t 趋近 1 和 0；**但现实中 GDN 的 α、β 强调「如何被输入调控」，并不强调沿时间步衰减。**

**苏剑林的回复（我摘要）:**
> 本文只是提供一个参考过程，表明**在什么假设之下** softmax attention 可以逐步近似为一个 GDN；从结果看，**k、v 越偏离它们的均值，误差越大**；由于 **softmax attention 本身没有什么就近原则**，所以线性化后出现「α、β 互补且随 t 趋近 1 和 0」的特点，**但真正自由参数化的 GDN，未必会去学出这种均匀的 attention，而是倾向于就近原则。**

> ⭐⭐ **两条可引用的限制:**
> 1. **有效性条件:k、v 越偏离均值，近似误差越大。**
> 2. ⭐ **推导解释的是架构形式的来源，不是训练后参数的行为** —— 推导出的 GDN 做均匀平均，真实训练出的 GDN 学到的是输入依赖的、带就近偏好的门控。**这两件事不能混为一谈。**

### 3.2 ⭐⭐⭐ 更根本的一条：两者理论上就不可严格互换

另一位读者问：有了 channel-wise 门控后，线性注意力就成了 softmax attention 解释不了的东西（包括 KDA）；若说全注意力＝无穷维线性注意力，那 KDA 该如何表示？

**苏剑林的回复（原文）:**
> 「虽然纯 linear 在 llm 上表现不如纯 softmax attention，但引入 delta rule 后的 deltanet 跟 softmax attention **本身就不是一方绝对优于另一方的存在**，比如 **delta rule 可以轻松做 state tracking，但 softmax attention 不行**，所以**它们俩理论上本就不是可以严格相互转换的模块**。」

> ⭐⭐⭐ **这句话是整个专题的枢纽。** ①② 两篇做的是「从 softmax 推出 GDN」，很容易让人以为线性注意力是 softmax 的一个受限近似、即天花板更低。**但他明确否掉了这个读法:两者是各有所长的两类模块，delta rule 能做 state tracking 而 softmax 做不到。**
> ⭐ **于是「用哪个」就不再是精度问题，而是取舍问题** —— 这正好把话题交给了 ③。

## 4. ③ K3 的实际取舍：为什么最后是混合

**K3 的架构一句话:`K3 = KDA + MLA + Stable LatentMoE + AttnRes`**，优化器仍是 Moonlight 版 Muon，但 Attention 权重改成 Per-Head 形式。
- **KDA** 出自 [Kimi Linear: An Expressive, Efficient Attention Architecture](https://arxiv.org/abs/2510.26692)（arXiv:2510.26692）
- **AttnRes** 出自 [Attention Residuals](https://arxiv.org/abs/2603.15031)（arXiv:2603.15031）
- ⭐ **Per-Head Muon 他讲得很诚实:「其实没有效果上的优势（当然也没有劣势），改用它更多是出于正确性考虑」**（每个 head 本就相对独立，不应耦合）

### 4.1 ⭐⭐⭐ 「比 MLA 更好的 Attention」必须同时满足四个条件

他把设计约束写成了一张清单 —— **我认为这是③里最可复用的一段:**

> 理想的、比 MLA 更好的 Attention 设计，**至少要同时满足:**
> 1. **效果不能差于 MLA**（保证效果）
> 2. **训练和 Prefill 成本至少不能超过 MLA**（计算效率）
> 3. **KV Cache 比 MLA 小**（超长文本）
> 4. **Decoding 的计算量比 MLA 小**（MTP 友好）
>
> ⭐ 「**至少在笔者现在看来，目前没有一个简单优雅的 Attention 设计能同时满足以上特点，所以我们必须有所取舍；而在跟 KDA 混合的背景之下，MLA 的部分问题得以缓解，所以我们依旧选择了 MLA。**」

**⭐ 他还举了一个被否掉的具体替代方案，说明这四条是真的在互相牵制:**
> 换成 256+256 的 MFA（本质是 MQA）效果能追回来、KV Cache 也不比 MLA 多，**但训练成本上去了，Scaling Law 上大概率吃亏；而且 Prefill 成本也增加** —— 「因为在当前主流的 Agent/Coding 场景下，每一轮的 Prefill 长度也不短。」

> ⭐⭐ **注意第 4 条的理由是「MTP 友好」、以及否决 MFA 的理由是「Agent/Coding 场景 Prefill 不短」** —— **架构选择被下游使用形态直接约束了**。这与我在 [[2026-08-12-muse-glimmer-30b-deep-dive]] 里得出的结论同构：Muse Glimmer 的 GQA 16:1 + 3:1 滑窗结构也是被「24GB 消费卡 + 131K 上下文」这个部署目标反向决定的。**两个模型、两个不同的约束来源，同一种设计逻辑。**

### 4.2 顺带：MoE 那半边有一个撞上我本周主线的发现

③ 的另一半讲 **Stable LatentMoE**，其中有一处与本仓库这周的评估主线直接相关：

- **SwiGLU 的病**：W₁ 某行与输入同向 → 输出巨大；若 W₂x 在同位置也发生 → **`O(‖x‖⁴)` 级异常值**。解法是 **SiTU-GLU**：门控用 softcap 版 SiTU（β₁=4），线性支路也加 softcap（β₂=25）
  > ⭐ 「给 SwiGLU 引入 Clip 已经不新鲜，**GPT-OSS、DSV4 已引入过 Hard Clip，但我们发现同样界限下 softcap 效果往往更好**。」
- **LatentMoE**（`d → d/2 → D → d/2 → d`，做 2n 选 2k）同成本下效果略好，**但四个矩阵连乘极不稳定**。加 RMS Norm 修复，消融发现**升维前那个最本质**，按最小改动原则只保留它。

> ⭐⭐⭐ **而这里有一句话直接撞上我这周反复记的主线:**
> 「多加的这个 RMS Norm，不止能稳定训练，还对效果有神奇作用。具体表现是，**在大家都能正常收敛的情况下，加不加这个 RMS Norm 对 Valid Loss 影响不大，但对于某些 Benchmark 来说，不加会稳定变差。**」（他猜测原因是它更好地平衡了 Routed 与 Shared Expert 的比例）
>
> ⭐⭐ **这是「一个数掩盖一个结构」的又一个案例，而且掩盖它的是 Valid Loss —— 训练时所有人最信赖的那个数。**
> **本周同型案例已经四个:**
> | 被掩盖的结构 | 掩盖它的那个数 | 出处 |
> |---|---|---|
> | 九个 harness 的真实差异 | correctness / task_succeeded | A²E（[[2026-08-11-hf-daily-papers-aug11b]]） |
> | 规则未被一致应用（52/160 部分成功） | ConceptARC pair 准确率 | BDH-CQ（[[2026-08-12-hf-daily-papers-aug11-12]]） |
> | 改对核心文件但漏掉外围 | resolve rate | SWE-Bench ProMax |
> | ⭐ **RMS Norm 对下游的影响** | ⭐ **Valid Loss** | **本篇** |
>
> ⭐ **前三个都在评估环节，这一个在训练环节 —— 说明「聚合指标掩盖结构」不是评估独有的病。**

## 5. ⭐⭐⭐ 原创交叉观察：两个 2026 旗舰模型都部分弃用了 RoPE，理由完全不同

**③ 里有一节讲 K3 的 MLA 把 RoPE 直接移除变成 NoPE。这一节让我立刻想到刚做完的 Muse Glimmer —— 它也用了 NoPE。但两者的理由毫无关系。**

### 5.1 K3 的理由：线性注意力隐含提供了广义 RoPE

- **前提事实**：K3 可以把 RoPE 加回去，**但加了之后效果看上去没啥变化，所以按最简洁原则就不加了**。
- ⚠️ **关键限定**：「**如果是 K2 这种全 MLA 模型，RoPE 是关键的，去掉 RoPE 会明显变差；K3 能用 NoPE，是因为它是「KDA+MLA」的混合模型。**」
- ⭐⭐⭐ **为什么混合就能 NoPE？他给了一条理论链:**
  1. 任意**正交矩阵的幂**都可以用作构建广义 RoPE（通常的 RoPE 选简单旋转矩阵，**PaTH** 则选 Householder 矩阵，表现也不错）
  2. 在正交情形下，PaTH 可等价写成
     `SoftmaxAttention( Q − DeltaNet(Q,W,W), K − DeltaNet(K,W,W), V )`
  3. ⟹ **给 Q、K 加 DeltaNet 也能起到类似 RoPE 的位置编码作用**；而 **KDA 是更一般的 DeltaNet**
  4. ⟹ 「**KDA+MLA 的混合模型，本身就自带类似 RoPE、PaTH 的位置编码效果。我们也可以说，K3 并不是没有 RoPE 了，而是 KDA 隐含提供了一种广义的 RoPE。**」

### 5.2 与 Muse Glimmer 并置

| | **Kimi K3** | **Meta Muse Glimmer 30B** |
|---|---|---|
| 结构 | **KDA（线性）+ MLA（softmax）** 混合 | **3 层滑窗 + 1 层全局** 重复 13 次 |
| 哪部分是 NoPE | ⭐ **MLA（softmax 那部分）整体 NoPE** | ⭐ **全局层 NoPE**，滑窗层用 RoPE(θ=5e5) |
| 官方给的理由 | ⭐⭐ **KDA 已隐含提供广义 RoPE，所以 MLA 不必再加** | ⭐ **用 RoPE 保留相对顺序与距离，用 NoPE 在全局层面保存信息** |
| 反证 | ⭐ **全 MLA 的 K2 去掉 RoPE 会明显变差** | （未给同类反证） |
| 我的核实 | 出自作者本人博文 | ✅ 在 `config.json` 的 `layer_rope_theta = [5e5,5e5,5e5,0,…]` 里核实过 |

> ⭐⭐⭐ **我认为这个并置本身是有价值的发现，因为它区分了两种完全不同的「NoPE 动机」:**
> - **K3 是「补偿型」**：另一个组件（KDA）已经提供了位置信息，所以这个组件可以不提供。**位置编码的职责被转移了。**
> - **Muse Glimmer 是「分工型」**：局部层负责顺序、全局层负责不衰减地保存信息。**位置编码的职责被拆分了。**
>
> ⭐⭐ **而 K3 的版本有一个 Muse Glimmer 没有的东西：一条反证（全 MLA 的 K2 不能去 RoPE）。** 这让「NoPE 之所以可行是因为混合」这个因果说法比单纯的设计陈述更可信。
> ⭐ **对我之前那份笔记的含义:** 我在 Muse Glimmer 里把 NoPE 记为「位置编码分层指派」这个趋势的实例，并说它比「K3 全面弃用 RoPE」信息量大。**读了③之后要修正一处——K3 并非「全面弃用」，而是只在 MLA 部分弃用、且理由是 KDA 已隐含提供。我此前从 Raschka 那里得到的「K3 全面弃用 RoPE」这个二手表述是不准确的。**

### 5.3 ⭐ 一个附带的「变更预算」表述

他还回答了一个审美问题：既然 MLA 不加 RoPE 了，为什么还保留另外拼接 64 维的做法？理由有三，最后一条值得记：
> 「**K3 已经引入了 KDA、AttnRes 等新变量，所以也不想往 MLA 引入太多的变数，毕竟饭要一口一口地吃。**」（另两条：更好适配现有 MLA 基建、不用重写代码；直接投影 576 维 Latent 虽更优雅但计算增加且效果无收益）

> ⭐ **这是一句关于「一次改多少」的工程纪律** —— 与 [[2026-08-11-hf-daily-papers-aug10-11]] 里 Evo-Bench 的失败分析（Qwen 把上下文与 verifier 改动**打包提交**，结果一个格式错误让 159/160 任务崩溃）正好互补：**那边是「打包改动导致无法归因」的反面教材，这边是「主动限制同时引入的变量数」的正面表述。**

## 6. ⭐⭐ 顺带一条路线之争：Linear+Full（K3）vs Sparse（DSV4）

③ 里有一节专门分析 DSV4 的 Attention，我认为它的价值不亚于讲 K3 自己。

**他的论点是「DSV4 看似放弃 MLA，实则是把 MLA 推到另一个极致」:**
1. 他此前两篇 MLA 博文的结论是：**「无形增大的 head_dims 是 MLA 效果的关键」**，且**「给定 KV Cache 大小下，效果最好的 Attention 是『一个 head_dims 等于 KV Cache 大小、K 和 V 共享的 MQA』」**
2. **DSV4 直接把 Attention 换成 `head_dims=512`、`K=V` 的 MQA（位置编码是 QKVO-RoPE）** —— ⭐ **而这正是 MLA 的 Decoding 形式**
3. 但这样训练与 Prefill 计算暴涨；且 **DSV4 没有线性注意力，每一层都有 KV Cache，即便每 token 只有 512 维也吃不消** → 于是引入 **Sparse（省计算）+ Compress（进一步压 KV Cache）**
4. ⭐ 「与其说 DSV4 放弃了 MLA，不如说它按照上述方向，**将 MLA 推到了另一个极致**……从 MLA 到 DSV4，**更像是一次传承和升级，而不是抛弃和重造**。」

**⭐⭐ 而他对两条路线的胜负给了一个明确的「不知道」:**
> 「不过，这种推广不是毫无代价，首先是 Infra 上的复杂性，其次是**如此激进地 Sparse 和 Compress，其最优性感觉还有待仔细检验**。」
> 「当然，『**Linear+Full**』路线也有它的不足之处，所以跟『**Sparse**』路线相比，**究竟谁能走得更远，目前还不得而知。**」

> ⭐⭐ **这给了我一个此前没有的框架:2026 年长上下文架构的两条主线不是「线性 vs softmax」，而是**
> | 路线 | 代表 | 做法 |
> |---|---|---|
> | **Linear + Full 混合** | **Kimi K3** | 用线性注意力承担大部分层，少量 full attention 保底 |
> | **Sparse + Compress** | **DeepSeek V4** | 全部保留 softmax 形式，用稀疏化省计算、用压缩省 KV |
>
> ⭐ **而 Muse Glimmer 属于第三种:滑窗 + 全局**（既非线性也非稀疏，而是把 full attention 限制在局部窗口）。**三种都是在同一组约束（效果/训练成本/KV/解码量）下的不同取舍点。**

## 7. 我的看法

**1. ⭐⭐⭐ 这个专题最有价值的地方是它同时给了「能推」和「不该等同」两面，而且出自同一人。**
①② 的推导很容易被读成「线性注意力是 softmax 的近似，所以上限更低」。**而他自己在评论区把这个读法否掉了:delta rule 能做 state tracking，softmax 不能，两者不可严格互换。** ⭐ **能从数学上把 A 近似成 B，不等于 B 是 A 的子集** —— 这是我从这个专题拿到的最一般的一条。

**2. ⭐⭐ 那四条 Attention 设计约束可以直接当选型清单用。**
效果不差于 MLA / 训练与 Prefill 成本不超过 MLA / KV Cache 更小 / Decoding 计算量更小。⭐ **而「目前没有一个设计能同时满足」这个判断，解释了为什么 2026 年的旗舰模型架构全是混合体而不是单一机制** —— K3（Linear+Full）、DSV4（Sparse+Compress）、Muse Glimmer（滑窗+全局）三个都是。

**3. ⭐⭐ 对我给客户做架构解释有直接用处。**
客户常问「线性注意力是不是要取代 Transformer」。**这个专题给的答案是有依据的「不会，会共存」，而且理由是可说清的:两者各有对方做不到的能力，且四条约束互相牵制。** 比泛泛地说「各有优劣」强得多。

**4. ⚠️ 我要修正自己此前的一处二手表述。**
我在 [[2026-07-27-blog-raschka-open-weight-roundup]] 相关记录里写过「Kimi K3 全面弃用 RoPE」。**读了③之后应更正为:K3 只在 MLA 部分弃用 RoPE（变 NoPE），理由是 KDA 隐含提供了广义 RoPE；而全 MLA 的 K2 去掉 RoPE 会明显变差。**「全面弃用」这个说法丢掉了最关键的条件。

**5. ⭐ 方法学上值得学的两点（与内容无关）:**
- ①② 里**每一处近似都标明了它的代价与有效范围**（截断破坏非负性、k/v 偏离均值误差增大、「q,k 模长相当」是假设）。
- ③ 里对自己团队的改动**明确区分了「有效果收益」与「只为正确性」**（Per-Head Muon 是后者）。⭐ **这种自陈在厂商技术博客里很少见。**

## 8. Open Questions

- ⭐⭐ **KDA 这类 channel-wise 门控的线性注意力，能否被 softmax attention 框架表示？** 评论区问了（「若全注意力＝无穷维线性注意力，KDA 该如何表示」），苏剑林回答**从理论拟合角度可能没问题，但要解析解会比较麻烦** —— 即目前无解。
- ⭐⭐ **推导出的 GDN（α、β 由 1/t 决定、做均匀平均）与训练出的 GDN（输入依赖、带就近偏好）之间的差距，能不能被量化？** 他明确说两者不同，但没给度量。**这是「架构形式的来源」与「架构学到的行为」之间的一个空白。**
- ⭐ **「Linear+Full」与「Sparse+Compress」谁走得更远？** 他自己说不知道。⭐ 这条值得作为一个跟踪项 —— **可观察的信号是后续旗舰模型往哪边靠。**
- **那个 RMS Norm 为什么「Valid Loss 不变但 benchmark 变差」？** 他猜是平衡了 Routed/Shared Expert 比例，但未做验证。⭐ **如果这个机制成立，它意味着 Valid Loss 对 MoE 的专家利用结构是不敏感的** —— 那是一个值得单独验证的判断。
- **①提到的截断后分量可能为负，在实际线性化实现里是怎么处理的？** 他只提醒要留意，未给方案。
