# Google AX：定位、运行机制与采用边界

核查日期：2026-11-11（Asia/Shanghai）。研究对象：`google/ax`，固定源码 SHA：`56bd0fc55574e48ad2ce952a7ea38730694d1fcf`。结论来自该版本的一手文档、protobuf 合同及选定实现的静态阅读。

范围为定位、公开接口、准入校验、部署清单、依赖、许可和路线图，并沿控制面、Substrate adapter、runner、workspace 与 model 的关键路径核对运行语义。这是源码研究，不是部署验证、全代码审计或性能复现。

证据分级：**静态确认**＝定义、配置或对应入口确实存在；**文档合同**＝官方这样描述，但本轮没有执行验证；**路线图**＝计划，不能写成已交付；**unknown**＝文档冲突、范围外执行细节或需要实测。文中源码链接均固定上述 SHA，行号是文件行号，不是网页抓取器的页面行号。动态发布网页另作标记。

阅读重点：AX 管运行环境与生命周期，不替你定义业务 Agent；文件恢复与会话恢复不同，环境就绪与任务成功不同，资源声明与能力实际接通也不同。第 8.1 节给出这些边界的具体源码证据。

## 1. 核心结论与定位

1. AX 是在 Agent Substrate 之上的声明式 agent 任务编排层，公开核心原语只有 `Task`、`Workspace`、`Model`，使用 `ax.io/v1alpha1` 和类似 kubectl 的 CLI。它不是因为 YAML 长得像 Kubernetes 就成为 Kubernetes operator/CRD API。官方架构明确选择 PostgreSQL 存储 AX 资源，再直接对接 Substrate。[AGENTS L10–16](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/AGENTS.md#L10-L16)、[DESIGN L3–7](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L3-L7)
2. “每集群百万任务”是 README 的规模定位/宣传主张，架构说明提供了避免 etcd 承载大量短寿命资源的设计理由，但不是压测报告。本轮未获得可复现百万任务测试、吞吐/延迟、硬件配置和成本数据，不能改写为“已经实测支撑百万并发运行”。任务记录量、挂起任务量与同时运行的 actor 数也应分开验收。[README L11–13](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/README.md#L11-L13)、[DESIGN L5–7](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L5-L7)、[WorkerPool 示例 L15–23](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/workerpool.yaml#L15-L23)
3. 成熟度应描述为快速开发中的 alpha 合同，而非稳定生产平台。README 直接警告稳定版前可能发生重大破坏性变化；SECURITY 明确指出 API 尚无认证授权，atespace 不是租户隔离边界。[README L6–9](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/README.md#L6-L9)、[SECURITY L9–16](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/SECURITY.md#L9-L16)
4. 安装不是“装一个 CLI 即可”：还包括 Kubernetes、Substrate、WorkerPool、快照存储、数据库、镜像构建/推送、集群身份与网络配置。当前 `go.mod` 已依赖 Substrate `v1.0.0`，安装指南则明确选择另一固定 AX 基线 `a496fc1ff1cf...` 和 Substrate `v0.6.0`。指南是针对该基线的配方，不能与当前 HEAD 的二进制和依赖混搭，也不是当前 SHA 的已验证安装流程。[go.mod L1–10](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/go.mod#L1-L10)、[installation L9–31](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/installation.md#L9-L31)、[installation L33–48](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/installation.md#L33-L48)
5. 研究与试点应优先验证任务生命周期、工作目录和产物，再分别验证所选 runner 的 MCP、模型凭据和预算约束。不能由 Workspace/Model 对象可创建，推导出注册表已解析、凭据已自动注入或模型调用已成功。[workspace.proto L35–83](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/workspace.proto#L35-L83)、[model.proto L31–43](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/model.proto#L31-L43)、[AGENTS L23–30](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/AGENTS.md#L23-L30)

### Task：生命周期、限制与不透明配置

- 新建任务按文档从 `Suspended` 开始，需 `ax resume` 启动；WorkspaceReady 表示环境已准备，Ready 表示 actor 运行且环境已准备。没有空闲 worker 时不能仅凭控制面正常就启动任务。[installation L248–267](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/installation.md#L248-L267)、[concepts L11–20](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/concepts.md#L11-L20)、[WorkerPool 示例 L17–20](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/workerpool.yaml#L17-L20)
- Task 创建后不可变；CLI 的 Task apply 实际调用 CreateTask，并非 Kubernetes 式就地更新。Workspace 与 Model 则调用 Update RPC。不要把“支持 apply”写成“所有资源均支持声明式更新”。重复创建的服务端重试语义仍需与 CLI 的 apply 行为分别验收。[DESIGN L42–65](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L42-L65)、[CLI L309–354](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax/main.go#L309-L354)
- 绑定的 Workspace 必须先存在于同一 atespace，多文档 apply 按文件顺序提交，应把 Workspace 放在 Task 前面；默认工作路径 `/workspace`，自定义路径要求绝对路径。[manifests L40–46](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/manifests.md#L40-L46)、[Task 准入 L34–42](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/apivalidation/task.go#L34-L42)
- 文档仅支持 CPU、memory limits；值需为正，CPU 小于 1000 cores；缺省维度为 1 CPU/512Mi。requests 虽出现在 protobuf 结构里，却被准入拒绝，不能理解成已支持 Kubernetes requests/limits 全套调度语义。[manifests L48–52](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/manifests.md#L48-L52)、[common.proto L30–38](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/common.proto#L30-L38)、[资源准入 L64–91](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/apivalidation/common.go#L64-L91)
- `spec.image` 应为 registry digest，而非可变 tag；manifests 的 Task 示例 L18 未带 digest，但紧随其后的规则明确要求 digest。抄示例必须修正；不符合会在 ActorTemplate 创建阶段失败。[manifests L11–38](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/manifests.md#L11-L38)
- config 是 runner 自己定义的对象，控制面只做边界校验，不解释 `goal`、`maxTurns` 等语义。JSON config 上限 16KiB，整体 Task launch YAML 上限 31KiB，数字精度敏感的 ID 应写成字符串；config 明文保存、可展示，不能承载秘密。[task.proto L46–52](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L46-L52)、[Task 准入 L52–103](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/apivalidation/task.go#L52-L103)、[manifests L54–60](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/manifests.md#L54-L60)
- 默认 runner 在 agent 命令退出后继续服务，业务成功不进入 Task 状态；runner 文档也明确命令退出码不被控制面读取。验收应另看产物/命令日志，不能把 Ready 当成功条件；实现证据见第 8.1.C 节，未实测。[runner L47–53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L47-L53)

恢复应按持久文件恢复和新进程启动理解，不承诺内存、调用栈或原会话原样续跑。这里已有 runner 文档支持；ActorTemplate 的具体 fidelity/volume 配置来源见第 8.1.B 节。[runner L20–27](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L20-L27)

### Workspace：环境描述与实际物化必须分开

Git/内联文件/skills 目录是 AGENTS 对内置 workspace 层的当前描述；同一文件明确说 MCP 是 spec-only，由 agent 通过元数据读取。concepts 和 sandbox 对 MCP/skills “准备完毕”的更宽描述不能独自证明默认 runner 已查询 registry、下载 skills 或启动 MCP 服务。[AGENTS L23–30](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/AGENTS.md#L23-L30)、[concepts L26–30](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/concepts.md#L26-L30)、[sandbox L14–19](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/sandbox.md#L14-L19)

沿实现核查，默认 skills 仅作目录准备，不写成自动下载/安装技能；具体 setupSkills 源码引用见第 8.1.D 节。文档中的 skills registry 字段不能作为实际解析、下载或认证的证据。[AGENTS L30](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/AGENTS.md#L30)、[workspace.proto L74–83](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/workspace.proto#L74-L83)

官方 Claude Code runner 文档是更窄的具体例子：它将显式 MCP servers（含 registry 内已显式列出的 servers）转成 `--mcp-config`；registry query **尚未解析**，不支持由 query 自动发现服务。HTTP endpoint 与 stdio command 分别有不同依赖，stdio 命令需已安装于镜像。这只是该 runner 的能力边界，不是默认 runner 的通用服务安装能力；实现来源见第 8.1.D 节，未运行验证。[Claude runner L72–100](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/claude-code/README.md#L72-L100)

### Model：配置对象，不是自动生效承诺

concepts 将 Model 说成可集中配置/换钥/调整参数；manifests 给出 google、anthropic 的例子。protobuf 中 Task 没有 ModelRef；单独的 Model 准入函数只验证 metadata。因此本轮能独立静态证明的是“配置合同及资源接口存在”，不能由 apply 成功推导供应商受支持、模型名有效、Secret 被正确读取、已有 task 被热更新。消费路径和 Secret namespace 的静态核查见第 8.1.E 节；运行中的轮换行为未验证。[concepts L32–36](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/concepts.md#L32-L36)、[manifests L102–146](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/manifests.md#L102-L146)、[task.proto L33–53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L33-L53)、[Model 准入 L19–23](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/apivalidation/model.go#L19-L23)

收束结论：Model CRUD 不自动决定所有 agent 的模型。Claude runner 的模型选项来自 `spec.config` 映射的 CLI flags，凭据示例来自 `spec.env`；不能把 Model 集中管理的愿景描述成所有 runner 已接入的统一调用链。模型包实际调用/导入搜索的证据见第 8.1.E 节；本稿不据此宣称模型包永远不可用。[Claude config L18–62](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/claude-code/README.md#L18-L62)、[Claude credentials L102–108](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/claude-code/README.md#L102-L108)

## 3. 当前接口与 Kubernetes 边界

- **CLI 静态确认**：apply/get/describe/delete，Task suspend/resume/ssh，以及 ctx、tunnel、version；范围旗标区分 AX atespace 与安装 AX 的 Kubernetes namespace。列出的接口不代表本轮已运行成功。[CLI L204–236](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax/main.go#L204-L236)
- **控制面 API 静态确认**：`ax.v1alpha1.AX` gRPC；Task 的 Get/List/Create/Delete/Suspend/Resume，Workspace/Model 的 Get/List/Update/Delete。没有 Task Update、Fork 或公开模型推理 RPC。YAML 由 CLI 解析后逐个发送 typed RPC，而非直接发给 Kubernetes apiserver；也不是多资源事务。[ax.proto L25–49](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/ax.proto#L25-L49)、[CLI L265–295](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax/main.go#L265-L295)
- **HTTP 文档合同**：控制面 8080 上 `/healthz`；9090 `/metrics`；task runner 80 上 probes/可选 guest gRPC，loopback `127.0.0.1:8099` 上 Task/Workspace YAML metadata。不能把这些 introspection 接口说成完整 REST 管理 API。[DESIGN L28–36](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L28-L36)、[observability L7–17](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/observability.md#L7-L17)、[runner L31–43](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L31-L43)
- **CRD 区分**：AX 的三种资源存于 PostgreSQL JSONB 表；部署 AX 所用 Namespace/Deployment/Service/StatefulSet 是 Kubernetes 对象。示例 `WorkerPool` 属 `ate.dev/v1`，是 Substrate 的另一套 API，不能改称 `ax.io/v1alpha1` 的 CRD。[数据库 schema L1–32](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/store/postgres/schema.sql#L1-L32)、[server 部署 L69–90](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/deploy/ax-server.yaml#L69-L90)、[WorkerPool L30–41](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/workerpool.yaml#L30-L41)

## 5. 架构层次：只按官方描述，不代替实现审查

1. **AX 控制层**：CLI 发送 gRPC，ax-server 做准入、锁与直接协调；PostgreSQL 保存资源描述与锁 lease。schema 有 tasks/workspaces/models 的 JSONB 表和 locks 表，支持这一持久化分层。[DESIGN L5–7、L28–32](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L5-L32)、[schema L1–40](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/store/postgres/schema.sql#L1-L40)
2. **Substrate 执行层**：文档分工为 atespace/actor 创建、激活与 worker 分配；AX 文档把 provisioned actor 的 phase/workerIP/Ready 描述为从 Substrate 读取，而不是全量复制到 AX store。状态组合和租约边界的静态核查见第 8.1 节；实际故障恢复未验证。[DESIGN L7–23](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L7-L23)
3. **task 内 runner/harness 层**：镜像需提供 `/usr/local/bin/ax-task-runner`；AX 不是直接把 `spec.command` 当容器 entrypoint。runner 读取 Task/Workspace YAML、准备工作目录、启动和监督子进程、提供 probe/metadata。默认镜像是 Python 3.12-slim 加常用工具；它不是仅凭 `config.goal` 就自动调用任意模型的完整 agent。[runner L9–25](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L9-L25)、[runner L45–53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L45-L53)、[默认镜像 L15–29](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/Dockerfile.task-runner#L15-L29)

架构文档明确数据库启动时创建缺失表、尚无版本化 migration；部署注释建议生产采用具备备份/failover 的托管数据库或 operator。分布式锁设计不能单独证明控制面高可用、灾难恢复或滚动升级安全。[DESIGN L7](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/DESIGN.md#L7)、[postgres L15–19](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/deploy/postgres.yaml#L15-L19)

## 7. 安全边界与运维验收建议

以下是研究建议，不是本轮已经完成的测试或安全修复。

1. **仅信任网络内试点**。SECURITY 明确 API 无 authn/authz，任何可达者均可操作资源；atespace 只是组织方式。建议不暴露到公网/不可信租户，先用可信客户端、网络访问控制和外层身份边界限定访问。即使按 Kubernetes context 自动连接，也不能当作 AX 内部资源级 RBAC。[SECURITY L11–16](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/SECURITY.md#L11-L16)
2. **区分三个通道**。AX 入站 CLI/API、AX→Substrate Control API、AX/CLI→router/guest 是不同边界。CLI `getAXClient` 明确使用 insecure gRPC；server 入口启用 unencrypted HTTP/2，不能以 `--server=https://...` 字符串或部署的 Substrate CA 推导 AX API 本身已有 TLS。[CLI L239–246](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax/main.go#L239-L246)、[server main L135–148](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax-server/main.go#L135-L148)、[部署 L94–98](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/deploy/ax-server.yaml#L94-L98)
3. **审查 Secret 权限与暴露面**。默认 ClusterRole/ClusterRoleBinding 给 server 集群级 secrets get/list/watch，规则没有按 namespace 或资源名收窄；建议按实际读取路径设计最小权限，并核对第 8.1.E 节的 Secret lookup。config 禁放密钥；Claude 示例把 key 代入 Task env 也不等于安全 Secret 引用或自动注入机制，env 的明文值存在 Task 合同中，建议把持久化与展示暴露列为专门验收项。[RBAC L28–48](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/deploy/ax-server.yaml#L28-L48)、[task.proto L46–58](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L46-L58)、[Claude credentials L102–108](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/examples/claude-code/README.md#L102-L108)
4. **debug 是执行权限开关，不是认证**。默认关闭；开启后 guest 提供任意进程执行与文件访问。能够创建 Task 的 API 客户端也能开启 debug，因而关闭默认值并不构成对创建者的权限约束。sandbox 内包括 runner 的反馈应按不可信处理，Ready 等状态不应用于安全决策。[SECURITY L13–16](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/SECURITY.md#L13-L16)、[runner L53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L53)
5. **固定并审计镜像供应链**。Task 使用 digest；构建的 server/runner、Substrate release 与 CLI 记录同一版本链。server/runner 基础镜像、apt/apk 依赖及 PostgreSQL tag 本身仍可变；Claude Dockerfile 默认 version=latest，还会执行下载的安装脚本。本轮只读这些文本，未执行安装器。[Dockerfile.server L15–22](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/Dockerfile.server#L15-L22)、[Dockerfile.task-runner L15–27](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/Dockerfile.task-runner#L15-L27)、[postgres L47–48](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/deploy/postgres.yaml#L47-L48)、[Claude Dockerfile L37–49](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/Dockerfile.claude-code#L37-L49)

### 8.1 执行路径：已确认的六个边界

**A. 一个 Task 绑定一个 Workspace；可复用的是配置，不是共享实时工作卷。**

TaskSpec 使用单个 WorkspaceRef，runner 读取这个引用及其路径。多个 Git repo 可以放进同一个 Workspace，但不能从 sandbox 文档里的复数措辞推导出多个绑定。新 Task 在同一 atespace 查找其 Workspace，随后确保 actor 存在并挂起；创建并不自动开始执行。[task.proto L33–53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L33-L53)、[server.go L181–214](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/server/server.go#L181-L214)

**B. 默认快照目标是工作卷，不是进程内存。**

BuildActorTemplate 的 PreferredFidelity 是 `SNAPSHOT_FIDELITY_VOLUMES`，只声明名为 workspace、挂载到 `/workspace` 的 durable directory。runner 合同也明确恢复到 fresh container/new process tree；重新启动后会再次走命令启动路径。不要把 `ax resume` 理解为恢复任意 Python 对象、活动连接或模型会话的内存状态。[Substrate adapter L365–403](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/substrate/client.go#L365-L403)、[runner 文档 L27](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/docs/runner.md#L27)、[runner.go L126–162](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/runner/runner.go#L126-L162)

采用建议：将任务进度、会话历史与结果回执明确写入 durable 路径，启动时恢复；外部行动要设计幂等键和去重。此建议不代表 AX 已提供 exactly-once。非默认 workspace path 是否真正进入持久卷也必须专门验证：当前 adapter 的卷挂载固定为 `/workspace`，Task 字段允许自定义绝对路径，二者不是自动等价。

**C. Running/Ready 是环境状态，不是业务成功。**

默认 runner 在子进程退出后调用日志/可选 OnCommandExit hook，然后继续等待取消，metadata/probe 仍服务。标准 runner binary 没有把这个 hook 接到 AX 的结果状态；Task 的 phase/Ready 则根据 Substrate actor 状态与 WorkspaceReady 组合得出。即便命令 exit 0 或 exit 非零，都不能只看 Running/Ready 判断其业务结果。[runner.go L158–201](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/runner/runner.go#L158-L201)、[runner binary L35–71](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax-task-runner/main.go#L35-L71)、[server 状态组合 L472–519](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/server/server.go#L472-L519)

应单独采集命令退出码、产物校验、验收结果和完成回执，并决定何时 suspend/delete。保留可调试环境有价值，但也意味着“程序退出”不自动结束 sandbox 生命周期；本文没有测量其资源或费用。

**D. 默认物化与注册表发现不是同一回事。**

默认 SetupWorkspace 写内联文件、拉取 Git，并用 setupSkills 创建所声明的 skills path；没有在这条路径查询 skill registry、下载技能或启动 MCP。Claude Code runner 另把静态 servers 和 registry 内已显式列出的 servers 转成 HTTP/stdio MCP 配置；它不使用 registry 的 provider/project/query 去动态发现服务。[workspace setup L106–119](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/workspace/setup.go#L106-L119)、[setupSkills L254–262](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/workspace/setup.go#L254-L262)、[Claude 配置 L148–174](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/runners/claude-code-runner/config.go#L148-L174)

因此“Workspace 可声明 registry”和“某个 runner 接入实际 MCP server”分别验收；要使用 stdio server，镜像内还必须有对应程序。这不是说外部自定义 runner 不能补齐这些能力。

**E. Model CRUD 不自动变成统一模型执行层。**

本次静态搜索全部非测试 Go 源码，未见 internal/model 的包外导入/调用；cmd/ax-server、默认 runner 和 Claude runner 的当前路径也没有消费一个 Task ModelRef。Claude runner 的 config.model 被转换成 Claude CLI 的 `--model`，它不是 AX Model 资源名引用。[server binary imports L29–35](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/ax-server/main.go#L29-L35)、[task.proto L33–53](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L33-L53)、[Claude flags L53–100](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/cmd/runners/claude-code-runner/config.go#L53-L100)

独立的 internal/model client 代码确实存在：远程实现针对 Google Generative Language API，其他 provider 默认报 unsupported；禁用远程或缺少 key 时返回合成 fallback。网络错误、401/403/429/503 也可能返回同类 fallback 和 nil error，token 数是字符串长度估算。这不是实测模型推理，也不能直接拿来做成功率或费用证据；该库未被接入上面的默认执行路径，不能说这些 fallback 已发生在所有 AX task 中。[model client L486–509](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/model/client.go#L486-L509)、[fallback 路径 L557–620](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/model/client.go#L557-L620)

Model Secret lookup 的库实现把 Config.Atespace 作为 Kubernetes namespace，并可回退到 kubectl 获取；这只是该库的机制，不证明任意 task 已自动接入 Secret。Claude 示例当前由 Task env 提供 Anthropic key。Task env 的类型是 name/value，完整 spec 又进入数据库与启动 YAML，因此“用 env 而非 config”不能自动等同于平台 Secret 引用或无明文持久化。[Secret lookup L270–385](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/model/client.go#L270-L385)、[Task env L55–58](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/pkg/apis/v1alpha1/task.proto#L55-L58)、[模板环境构造 L180–203](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/controller/reconciler.go#L180-L203)

**F. 两处需要故障验收的静态发现。**

1. **Git 失败可能仍获得就绪响应。**SetupWorkspace 在 Git 失败时不写初始化 marker，但返回 `res,nil`；runner 只看 error，nil 时 SetWorkspaceReady(true)，随后仍进入 command 路径。由这两个分支可推出默认组合存在“仓库拉取不完整却就绪”的路径；这是静态推断，没有运行失败注入测试，不能推广为每个自定义 runner 都这样。[setup.go L106–119](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/workspace/setup.go#L106-L119)、[runner.go L126–150](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/runner/runner.go#L126-L150)
2. **数据库租约不提供完整 fencing 保证。**PostgreSQL Locker 用数据库时钟、短 TTL 和续租组织跨副本互斥，但源码明确写出没有 fencing token：长期续租失败后，旧 holder 可继续执行，锁丢失只记日志。不能由“有分布式锁”直接推出网络分区下仍严格串行或 exactly-once。[lock.go L29–69](https://github.com/google/ax/blob/56bd0fc55574e48ad2ce952a7ea38730694d1fcf/internal/store/postgres/lock.go#L29-L69)

### 8.2 适用场景与试点建议

我的判断：AX 值得作为隔离代码 Agent、批量执行任务和长期环境生命周期的基础设施学习对象；如果已有 Kubernetes/Substrate 运维能力，可以在可信、非生产环境评估。判断依据是其 Task/runner 的小接口及可替换镜像设计，不是对部署成功或吞吐的承诺。

若需求主要是写对话、工具调用或推理图，先实现业务 Agent，再决定是否需要 AX 承载它；AX 不替你定义那一层，也不提供本次已核实的通用跨会话记忆整理服务。无需因为它来自 Google 就让它成为默认生产底座，尤其不要跳过当前明确缺失的入站鉴权与租户边界。

建议试点按下面顺序验收，而不是一开始追求大规模：

1. 固定 CLI/server/runner/Substrate 版本与镜像 digest，先运行无模型、无业务秘密的 Task。
2. 保存文件和完成回执；suspend/resume 后检查恢复文件、进程重启及是否重复执行。
3. 故意使 Git/命令失败，分别检查 WorkspaceReady、Ready、退出码和业务结果。
4. 接入显式 MCP 服务与自行管理的模型凭据，核验所选 runner 的实际使用路径。
5. 在外层建立访问控制、egress、模型支出限制、审计与清理，再测并发/快照/故障恢复。

以上均为建议，没有执行试点、购买服务或创建云资源。
