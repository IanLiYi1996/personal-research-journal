## 🚨⭐⭐ 一、`Grouped Value Attention`（18▲）—— 它给我那份 softmax 线性化专题里的四条判据交了一份答卷

**机制**（摘要，⚠️ 仅摘要）：

> KV cache 是 Transformer 解码的主要瓶颈（内存与缓存读流量随序列长度增长）。**GQA 靠共享 KV head 降成本，但仍然在每一步同时存 key 与 value。**
> ⭐⭐⭐ **GVA 只存 grouped values，并用一个学出来的线性映射重建 content key；推理时那个映射可以被吸收进 query，从而在既定的解码路径上完全不需要物化 content key。** 位置信息由一个小的共享 decoupled RoPE 通道、经一个单独缓存的 positional key 保留。

**数字**：

| 量 | 值 |
|---|---|
| 持久缓存标量数（对齐 GQA）| ⭐ **减少约 45–47%** |
| 350M 参数 / 30B FineWeb-Edu token、五个任务平均准确率 | **GVA(16 维位置变体) 44.18 vs GQA 44.36 vs MLA 43.88** |

⟹ ⭐⭐⭐ **而这恰好可以拿我 [[2026-08-12-topic-softmax-linearization-and-k3]] 里记的那四条判据去对**（苏剑林给「比 MLA 更好的 Attention」定的四条：效果不差于 MLA / 训练与 Prefill 成本不超过 MLA / KV Cache 更小 / Decoding 计算量更小）：

- ✅ **效果不差于 MLA**：44.18 > 43.88
- ✅ **KV Cache 更小**：−45~47% vs GQA
- ⭐ **Decoding 计算量**：「映射被吸收进 query、不物化 content key」直接指向这一条
- ⚠️ **而它对 GQA 是略低的（44.18 vs 44.36，差 0.18pp）** ⟹ ⭐⭐ **这是一份诚实的取舍报告而不是「全面更好」，措辞用的是 `near-GQA benchmark accuracy with a more compact cache representation`。**

⭐⭐ **机制上值得记的一点：「把 key 的重建映射吸收进 query」与我 08-12 记的「MLA 的 Decoding 形式就是 head_dims=512、K=V 的 MQA」是同一类代数变换** —— **把一个矩阵吸收进另一侧以避免物化中间量**，⟹ ⭐ **这类变换在 KV cache 这条线上反复出现，它本身可能是这个子领域的主要工具。**

⭐ **而它与我 09-10 记的那条 LessWrong（`Recurrent KV-cache sharing may undermine the bounded-depth argument`）落在同一套机制上** —— 那条说「递归 6 覆盖递归 1 的槽位、下一 token 的浅层读上一 token 该槽 ⟹ 每 token 递归有界而整条 rollout 的不透明串行深度随长度增长」⟹ ⭐⭐ **若那个论证依赖 KV cache 的槽位结构，则一个改变「缓存里到底存什么」（存 value + 一个位置 key、不存 content key）的架构会改变该论证的适用性。** ⚠️⚠️ **这是我的推断，两篇互不相干，且我只读了 GVA 的摘要。**

⚠️ **保留**：**规模只有 350M / 30B token**，而 GQA/MLA 的取舍在前沿规模上可能不同（⭐ 而这正是 NCP-ArchPreview 今早那个 Δloss「先收窄再扩大、转折约在 3.5T」所警告的事——小规模上的结论不能外推）；摘要在「we have de…」处截断，实际加速数字我没拿到。

## 🚨⭐⭐⭐ 二、`MInTRL`（仅 1▲）—— 它把「只改该改的」推到了第四个层次，且与我一周前深读那篇综述里的一个机制几乎相同

**它的问题陈述正是我追的那个张力**：

> RLVR 通常是 on-policy 的，**把训练数据保持在当前策略附近，但也把学习限制在策略自己能发现的轨迹上**；而 off-policy 方法（如 SFT）**能利用超出基座模型能力的外部知识，但会有大的分布偏移**。⭐⭐⭐ **「The key challenge is thus to expand exploration without sacrificing learnability.」**

**机制**：**Minimal Intervention RL** —— 在整体上仍然 on-policy 的 rollout 里插入**稀疏的局部干预**：

> ⭐⭐⭐ **生成期间，一个 judge-intervention 策略周期性地检查当前策略的输出，把错误的后缀替换成简短的修正，然后立刻把控制权交还给策略。**
> 训练期采用**序列级 advantage-regression 目标，从而不需要 importance sampling**。

⟹ 🚨⭐⭐⭐ **这与我 09-08 深读那篇 OPSD 综述里的 `step-aligned critique` 是几乎同一个机制，而两者在不同范式上**：那个是「一个 critic **逐字复制学生推理中正确的步骤、只重写错误的那些**、且用学生自己的风格」，比条件于参考解的 OPSD 高 **+5.27**；⭐ **而那篇的 per-token advantage 分析给了机制：「看到参考解时模型在每一个 token 上都修改行为，包括已经正确的；aligned critique 只改错误的」。**

⟹ ⭐⭐⭐ **由此「只改该改的」这条线今天变成四个层次，且四篇互不引用**：

| 层次 | 篇 | 数字 |
|---|---|---|
| **梯度层** | step-aligned critique（09-08 那篇综述转引）| 比参考解 OPSD +5.27 / 比 GRPO +16.11 |
| **代码编辑层** | When Models Edit Too Much（09-08）| 多余 Levenshtein 0.195→0.131、复杂度 −26.6%、⭐ **Pass@1 反而 +2.3** |
| **harness 演化层** | DarwinX 的有界回退契约 | `g(c)>0 ∧ R(c)≤δ` |
| 🚨 **RL rollout 层（本篇）** | MInTRL | ⭐ **只替换错误后缀、立刻交还控制权** |

⟹ ⭐⭐ **而四个层次的共同形状是同一句话：不要从头重写，只生成对一个已有产物的有界修改** —— 这也正是我 08-14 从 DarwinX/SKILLER/AutoPrune 三篇归纳的那条（「不要从头生成，只生成对一个强基线的有界修改」），⭐ **而本篇把它推到了 RL 的采样过程里，那是这条线此前没有的位置。**

⭐⭐⭐ **另一处更值得记：它与我今早刚命名的「锚定式代理」是同一结构，而今天已是第三个实例** ——

| 实例 | 主体流程（便宜）| 锚（贵但可靠，稀疏保留在环内）|
|---|---|---|
| **WMRL**（452▲，今早深读）| 世界模型替换环境执行 | ⭐ **一小股真值留在训练循环内** |
| **PLC-DPO**（25▲，今早）| 带噪声与歧义的偏好标签 | 后验标签校正 |
| 🚨 **MInTRL**（本篇）| 整体 on-policy 的 rollout | ⭐ **稀疏的 judge 干预** |

⟹ ⭐⭐⭐ **三篇互不引用、范式各不相同（RL 的奖励源 / 偏好学习的标签 / RL 的采样轨迹），而结构完全一样：允许便宜的主体流程，但强制它被一小股更可靠的东西持续锚住。** ⟹ ⭐⭐ **这让我今早那个「第三类」从一个观察变成了一天内三个独立实例支撑的类别，而它此前只有 WMRL 一篇。**

⚠️ **保留**：仅摘要（1▲，无 HTML 版检查、正文未读）· **摘要在 `while preserving the overall on-policy nature` 处截断，具体数字一个都没有** ⟹ **我引的是它的机制与问题陈述，不是任何效果。** ⚠️ 而「judge-intervention 策略」本身是谁、有多可靠，摘要没说 —— ⭐ **而这恰是「锚定式代理」这一类的承重点：锚必须比主体流程更可靠，否则它只是另一个代理。**
