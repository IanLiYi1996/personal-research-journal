RSI：AI 能不能学会改进自己？

先弄清系统改进了什么，再看实验能支持怎样的结论。
这份中文阅读版串起研究脉络、代表工作与尚未解决的问题。

讨论 AI 的递归自我改进，最容易跳到一个很远的问题：它会不会越来越聪明，最后进入“智能爆炸”？但读过具体实验之后，会发现研究者眼前的问题要小得多，也更容易检验。

一个 AI 改写了自己的工具，下一次任务做得更好了。这个结果有价值。不过，如果想知道递归自我改进是否成立，还得接着问：新版本有没有更好的办法发现问题、提出修改、判断修改是否有效？换一批任务，它还能继续这样改进吗？

这份阅读版围绕这些问题展开。我的判断是，局部自改进已经有可研究的实验系统。2026 年的一些工作也开始直接测量“改进能力”。持续自加速则仍缺少足够的证据，不能把它当作这些论文已经证明的结论。1

01先把“递归”讲清楚

RSI 是 Recursive Self-Improvement 的缩写，通常译作“递归自我改进”。这里的递归，指的是系统修改自身之后，新版本又参与下一轮改进。

可以用一个写程序的 AI 来理解。它第一次修复代码失败，读了报错信息后重新作答，这叫利用反馈改进答案。如果它发现自己的文件搜索工具不好用，于是改写工具，并在以后的任务中保留这个修改，改进的对象就成了系统。如果它又学会了更好的错误诊断和修改方法，下一次能用更少尝试找到有效改动，就开始触及更强的递归改进问题。

这几种情况经常出现在同一套实验里，却不能用同一个分数概括。

Self-Refine 和 Reflexion 让反馈、反思和记忆帮助后续尝试，是理解这个领域很好的入口。但它们的收益，不能自动当成“产生改进的方法也变强了”的证据。2

“改自己”也不一定意味着修改神经网络参数。AI 智能体通常由基础模型、工具、记忆和控制程序组成。论文里的 agent 是这套执行任务的软件系统；harness 指围绕模型安排上下文、工具调用和执行流程的程序。修改这些程序，可能在模型参数不变时提高表现。读论文时，先确认改动发生在哪一层，会省下很多争论。

本篇把“任务做得更好”和“更善于产生下一次改进”分开讨论。这是一个阅读和实验分析方法，不是学界已经统一的 RSI 定义。

02为什么这个问题一直被讨论

1965 年，I. J. Good 提出了一个条件性的设想：如果机器的智力活动全面超过人，其中也包括设计机器，那么它就可能设计出更好的后继机器。这解释了“智能爆炸”一词为什么会和 RSI 联系在一起。但原文是推测，没有给出实际增长曲线，也没有建造这样一台机器的方法。3

Schmidhuber 后来提出 Gödel machine，把自修改写进一个形式化决策模型。系统需要在给定的公理、环境假设和效用函数下，找到足以支持修改的证明，才执行自修改。这套理论值得读，尤其是它如何把继续搜索的成本也纳入决策。它的困难同样明确：有用的修改未必可证明；即使可证明，系统也未必能在可用资源内找到证明。4

现实中的大语言模型智能体大多走另一条路。它们通常先提出修改，再运行测试，看修改有没有用。数学证明被有限实验替代，工程上更容易做，证据要求也随之改变：测试有没有泄露？筛选候选用了多少资源？效果能否迁移到没见过的问题？

这个领域还有一条容易被 LLM 热潮遮住的历史。早期 learned optimizer 研究让神经网络学习参数更新规则；2022 年的自指权重矩阵和自指元学习工作，则研究权重、记忆及学习机制怎样参与自身更新。它们提醒我们，RSI 的研究对象可以在神经网络内部，也可以在外部软件中。那些实验仍有固定架构和简化任务的限制，不能直接推到长期自主学习。5

03现实系统是怎样改自己的

改提示词，也改产生提示词的方法

Promptbreeder 很适合用来理解递归发生的位置。它同时进化两类提示词：一类用于解任务，另一类告诉模型怎样修改前一类提示词。这样，“产生变化的方法”也成了可修改对象。6

STOP 把类似思路放到代码里。先有一个调用语言模型改进代码的程序，再让这个程序改进自己的实现，得到新的代码改进器。底层语言模型没有随之训练，变化发生在调用它的程序上。7

这两项工作的好处是对象清楚：你可以分别冻结解题策略、修改策略，检查收益到底来自哪里。它们并没有证明改进可以无限持续，但为研究改进方法本身提供了相对可控的起点。

改智能体的工具和执行流程

ADAS 把 agent 设计变成程序搜索：元智能体提出新设计，评测后放进档案，再继续探索。SICA 则让编码智能体修改自己的源码，包括工具、代码定位和上下文管理。8

Darwin Gödel Machine，简称 DGM，是这条路线里值得细读的系统。它让编码 agent 提出自身修改，用实际任务检验效果，并把可运行版本保存在档案里。后续搜索可以从不同分支继续，不必每次都只沿着当前最高分版本走。9

DGM 报告的 SWE-bench 成绩从 20% 上升到 50%。读这个数字要保留设置：本篇采用的更新版论文使用分阶段评测，较强候选扩展到 200 题，不是完整 500 题排行榜口径。基础模型权重和外层进化规则也没有一起改写。

这项工作支持一个具体结论：编码智能体可以通过软件修改，在限定任务中找到有用的自身改进。它还报告迁移实验，帮助判断效果是不是只记住了演化过程中的任务。要进一步讨论持续递归增长，就必须测量新版本产生后续改进的能力，不能只延长已有的任务分数曲线。

SICA 的 17% 到 53% 也来自 50 题子集。两个系统的数字可以帮助理解各自实验，不适合直接拿来给 RSI 系统排强弱。8

改学习材料和模型参数

SEAL 研究的是另一种闭环。模型先生成适合自己微调的材料或配置，完成参数更新后，再根据下游表现，学习怎样生成更有效的更新材料。10

它把“学习新内容”和“学习怎样准备学习材料”连在一起。这里不只有软件流程变化，也涉及模型参数适应。

实验仍需要逐项解读。更新版论文里，ARC 少样本部分用了 8 道筛选题，每题尝试 5 个自适应配置，共 40 次配置试验。72.5% 是这些配置带来适应成功的比例，不能读成完整 ARC 题库的通过率。论文还测量了遗忘：新知识学进来了，不代表旧能力都保留了。

Absolute Zero Reasoner，简称 AZR，让系统自己生成代码相关推理题，再用执行器检查任务并提供奖励。它降低了对人工训练示例的依赖，但仍有预训练模型和执行环境作为基础。“零数据”不能理解为没有任何知识来源或外部正确性信号。11

这条路线值得追问的是，系统会不会越来越擅长生成自己容易得分的题，而不是越来越擅长解决新的难题。

改支撑 AI 研发的算法

AlphaEvolve 将模型生成程序、自动验证和进化搜索组合起来，优化算法和计算程序。Google DeepMind 报告过数据中心调度和模型训练内核的实际应用。12

其中一个训练内核加速 23%，对应整个模型训练时间约降低 1%。这两个数必须一起读：局部程序的加速，不能当成端到端训练的同等加速。

这一方向的工程意义很直接。它还提供一个可以继续研究的反馈问题：省下来的计算，是否真的用于下一轮研发？扣掉搜索和验证成本之后，研究效率有没有净增加？AI 优化了支撑 AI 的程序，是这个问题的起点，还不是完整闭环的证明。

042026 年：开始直接检验“更会改进”

Hyperagents：给改进能力单独设计一个测试

Hyperagents 让执行任务的 task agent 和产生修改的 meta agent 同处于一个可编辑程序中。这样，系统不只改任务执行代码，也能改产生下一次修改的逻辑。13

它的实验引入 improvement@k，可以把它理解成：给一个固定的改进器 k 次产生候选版本的机会，用验证集选出候选，再在独立测试集上测量它带来的增益。这个指标试图测量“更会改进”，而不只是测量某个最终版本多强。

论文报告了把从论文评审、机器人奖励设计中形成的机制迁移到数学解答评分的正面结果。不过，初始数学评分系统有输出格式和解析问题，零分提升不能全部归因于数学能力增强。迁移还同时带入了 task agent 和 meta agent 的代码，后续可以进一步拆开这两部分的贡献。

更长的继续演化实验里，迁移初始化与原始初始化的最终差异没有达到显著水平。所以，这项工作提供了更直接的跨域改进证据，却没有证明收益会一直复合增长。

AIDE²：把“是否点火”作为实验问题

AIDE² 的研究智能体会修改自己的研究流程代码，再由外层评测决定是否接受修改。一条报告的轨迹持续 8 天，有 100 个搜索树节点，接受了 7 次修改。这里的节点是候选程序版本，不是 100 台机器。14

论文在未参与候选选择的研究基准上检查了迁移。但它更值得注意的一步，是把改进后的研究智能体拿来做外层改进器，测试它是不是更会推动下一轮自改进。作者把这个实验称为 ignition test。

结果尚不确定。每组只有三次独立运行，噪声和成本限制了判断，不能据此宣布自加速已经“点火”。

我更看重它提出的可检验问题。如果一个系统号称自己越来越会做研究，那么应该让新旧版本在相同条件下继续开展研究，比较它们产生有效改进的效率。

其他进展，可以放回各自的修改对象里理解

EvoX 和 Dream-RSI 主要修改搜索或探索策略。它们研究系统怎样选择下一次尝试、怎样从已有发现中安排计算，较接近改进方法的优化，但更上层生成器和评价规则仍有固定部分。15

GEA 和 MetaShare 侧重经验共享：不同演化分支不必各自忘掉失败，修改及其成败记录可以供其他分支使用。收益可能体现为更早找到好版本，但不能只数演化代数，还要算总调用和总计算。16

Meta-Harness 优化固定模型周围的执行程序；AREX 主要递归细化研究答案、证据与上下文；VisionHOPE 研究图像处理过程中自引用的记忆更新。它们都可以放进更宽的自改进研究地图，但不必因此假定它们证明了同一种 RSI。17

05那些上涨的曲线，究竟说明了什么

这一领域最难的部分之一，是给上涨的分数找到正确解释。

首先要检查是不是用了更多资源。如果一种方法生成更多候选，再挑出最好的结果，分数可能上升，改进策略却未必变强。DGM 报告的一个演化运行估计成本约 22,000 美元，两个消融基线各约 10,000 美元。预算差异不证明它无效，但说明同预算比较很有必要。9

还要检查模型有没有变。Gödel Agent 的不受限设置允许修改 API 调用，部分额外收益来自使用更强模型。换模型可以是合理的系统优化，却不能全部计入递归机制的贡献。18

任务信息流同样重要。如果系统反复根据同一批题的反馈选择版本，它就可能逐渐适应这批题。DGM 在改进诊断中使用了私有测试补丁信息，作者报告没有发现硬编码答案，也给出了迁移结果。合理的读法是分开看演化内成绩和独立迁移成绩，而不是只凭这件事断言作弊。

最后，分数本身可能不够可靠。奖励模型研究观察过代理评分继续上升，而较独立的评价开始下降。内部评分器可以参与学习，但不能同时充当唯一的终审者。19

负面论文也需要这样读。没有外部反馈的提示式自纠错，在某些设置中会把正确答案改错；后续 SCoRe 通过训练改善了自纠错，训练时仍使用正确性奖励。递归合成数据可能丢失分布信息，保留和累积原始数据又能在相应设置下缓解退化。它们限定了哪些方法容易失败，没有证明所有自改进都不可能。20

研究自动化基准提供了有用任务。MLE-bench 测机器学习工程，RE-Bench 测一组 AI 研发环境。但最终任务成绩、重复尝试的成功率和下一轮改进能力，仍是不同指标。若要用这些基准研究 RSI，需要增加新旧改进器的对照，而不能只报告最后一次提交的成绩。21

06如果要做研究，我会选什么

先研究改进器是否真的变强

我会从一个已经能正常执行任务的简单编码智能体开始，不急着复现完整的大规模搜索。让不同方法从相同初始版本出发，固定基础模型和预算，比较固定改进器、可修改改进器、普通进化搜索，以及多次采样后选最好的方案。

真正有辨识度的实验在下一步：把这些改进器带到新的任务家族，重新开始改进。如果新版本仍能用更少资源找到有效修改，就比一条原任务上的上涨曲线多了一层证据。

Hyperagents 的改进能力指标和 AIDE² 的 ignition test，可以作为设计参照。它们也暴露了值得补强的地方，例如把任务执行代码和改进器代码分开迁移，避免初始版本的格式错误主导结果。

把验证器做成一个独立研究对象

系统需要知道修改有没有用，而这个判断可能出错。一个实用课题是研究：哪些检查能拒绝无效修改，又不会错杀真正有用的修改？隐藏测试、独立反例、执行轨迹交叉检查，都可以成为实验变量。

我会让系统修改工具和策略，但把最终测试、预算限制、权限边界及审计日志放在修改范围之外。这里的目标是保证能力评价可信，不是让系统获得尽可能大的自由度。

有训练资源，再研究多轮适应

如果关注模型训练，可以沿着 SEAL 研究连续适应：每轮加入新知识，同时复测早期知识和通用能力。比较自生成学习材料、固定材料和其他适应方法时，应控制训练量，而不是只看新任务收益。

如果关注课程生成，可以沿着 AZR 检查任务难度、多样性和未见任务的迁移。系统自己出题并不自动保证课程质量。

这些是我的选题建议，不是已经完成的实验。它们的共同目标是让结论能够归因：收益究竟来自改进方法，还是来自更多计算、记住题目、改变评分方式？

07怎样继续读这个领域

如果只想先理解当前讨论的焦点，可以按 DGM、Hyperagents、AIDE² 的顺序读。DGM 展示自修改系统怎么运行；Hyperagents 尝试单独测改进能力；AIDE² 进一步检验改进后的研究者能不能推动下一轮自改进。

如果更关注实验可控性，先读 Promptbreeder 和 STOP。它们的修改对象相对清楚，适合拆开机制做对照。关注参数学习时，再读 SEAL、AZR 和神经自指学习的论文。

每读一篇，只需先记住几个问题：它修改了什么？哪个部分仍固定？谁判断修改有效？最终测试有没有参与候选选择？总共花了多少资源？新版本有没有在新任务上更会产生改进？

读完这批材料，我对 RSI 的兴趣主要落在最后一个问题。现在已有系统能提出并保留有用的自身修改，也有研究尝试测量改进机制的迁移。下一步需要的是更扎实的比较，说明这种能力在什么条件下持续，在哪里停滞，哪些成本和错误会累积。关于长期自加速的判断，应建立在这些实验之上。
