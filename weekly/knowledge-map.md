# 知识地图：这个 journal 里长出了什么（基于图谱数据的人工解读）

- **Date:** 2026-07-30
- **Tags:** #meta #knowledge-graph #knowledge-management

> 这是对 [知识图谱洞察报告](/weekly/knowledge-graph.md)（脚本自动生成）的**人工解读**。图谱本身可交互浏览：[🕸️ 知识图谱](/graph.md)（点击节点直接进入笔记）。
>
> **方法来源**：分析方法参考 [nashsu/llm_wiki](https://github.com/nashsu/llm_wiki)——它是 Karpathy 「LLM Wiki pattern」的桌面应用实现。我没有安装那个应用（它会另建一套 wiki 数据、与现有 Docsify 工作流重复），而是把它的三个核心方法搬到本仓库现有文件上：**4 信号相关性模型** + **Louvain 社区发现** + **Graph Insights（意外连接 / 知识缺口）**。

## 0. 一句话

**104 篇笔记、160 条关联、37 个社区**。图谱证实了一件我原本只是感觉的事：这个 journal 的重心已经从"每周抓取"沉淀成**三个有内聚力的知识块**（Agent 长程体系 / LLM 效率与长上下文 / 量子计算），但同时有 **43 篇孤立笔记（41%）** ——大多是历史 digest，它们贡献了素材却没有被后续综述"回链"。

## 1. 图谱确认的三个知识块

| 社区 | 规模 | 内聚度 | 是什么 | 核心笔记 |
|---|---|---|---|---|
| **#13** | 20 | 0.20 | **每周抓取流水线**（HF/Reddit/Tech-blogs 三源交叉） | Raschka 架构横评、W31 Reddit、HF jul28-29 |
| **#7** | 16 | 0.27 | **LLM 效率与长程能力**（本月新长出来的） | 长程 agent 整理、推理努力度、长上下文 |
| **#3** | 14 | **0.47** | **Agent 体系演化**（最成熟的一块） | agent-evolution、ai-frontier-comprehensive |
| **#29** | 7 | **0.48** | **量子计算**（完全独立） | quantum-intro / frontiers / industry |
| **#2** | 4 | **0.83** | **harness 工程**（内聚度最高） | two-harness-comparison、harness-survey |

**读出来的三件事**：

1. **社区 #2（harness 工程）内聚度 0.83，是全图最紧的**。4 篇笔记几乎两两互链——说明这个主题我做得最系统、交叉引用最自觉。这是"好知识块"的样子。
2. **社区 #7 是本月新长出来的**（长上下文 / FlashAttention / 推理努力度 / LongStraw / Kimi K3 全在里面）。内聚度 0.27 还不算高，但考虑到它们是**同一周内写的**、且我刻意做了交叉引用，说明"写的时候就想着串联"确实有效。
3. **量子计算（#29）完全孤立于所有 AI 主题**——内聚度 0.48 说明它内部自洽，但与主线零连接。这不是缺陷，是**兴趣的真实分区**。

## 2. 三个桥节点：知识网络的承重墙

脚本识别出仅 3 个笔记连接了 ≥3 个社区：

| 笔记 | 跨社区 | 连接数 |
|---|---|---|
| **长程 agent 研究路径全景** | **4** | 12 |
| Agent 体系演化谱系 | 3 | 11 |
| Agentic RL Survey（论文笔记） | 3 | 4 |

**这个结果让我意外但事后想很合理**：[长程 agent 整理](/research-notes/2026-07-20-long-horizon-agents.md) 是全图唯一连接 4 个社区的节点。原因是它的"两支柱框架"天然需要引用架构（长上下文）、训练（RL）、harness、评测四类知识——写的时候我确实刻意把五篇点状笔记连成网，图谱把这个意图**客观量化**出来了。

**运维含义**：桥节点是网络的**单点故障**。如果这 3 篇之一过时或写错，会同时污染多个知识块。它们值得优先复审。

## 3. 意外连接：图谱发现的、我没意识到的关系

这是 llm_wiki 方法里最有价值的一环——**自动找出跨社区/跨类型却强关联的笔记对**。前几名：

| 分数 | 连接 | 为什么意外 |
|---|---|---|
| **4.79** | Raschka 架构横评 ↔ W26 Reddit 周报 | 一篇技术深读 vs 一篇社区舆情，却共享文献。说明**社区讨论与架构分析在追同一批模型** |
| **3.90** | Anthropic global workspace ↔ 推理努力度综述 | 权重 4.0 但**零共享文献**——纯靠我手写的交叉引用连起来。这是"人工洞察"而非"文献重叠"，恰恰最有价值 |
| **3.43–3.42** | two-harness 对比 ↔ agent-evolution / ai-frontier / trends（三条） | 一篇 research-note 同时锚定了三篇 topics 页——它实际是**跨块的翻译层** |
| **3.37** | CoT 机制小综述 ↔ Agentic RL Survey | CoT 与 agentic RL 被我分开写，但图谱认为它们该连——**这是个真实的补链机会** |

**最值得记的一条**：第 2 名（global workspace ↔ 推理努力度）**共享文献数为 0**,连接全部来自我自己写的 `[[链接]]`。这说明**手写交叉引用产生的信号,图谱抓得到、且权重很高**——继续保持写笔记时手动串联的习惯是有回报的。

## 4. 知识缺口：43 篇孤立笔记说明什么

**43 / 104 = 41% 的笔记 degree ≤ 1**。分类看：

| 类别 | 典型 | 该不该补链 |
|---|---|---|
| **历史 HF digest**（apr7-8、jun13-16…） | 一次性周报 | ❌ **不必**。它们是**素材层**，使命是被综述消费掉。孤立是正常的 |
| **LLM 入门系列 8 篇**（llm-intro-*） | topics/llm/ 下整套 | ⚠️ **该补**。8 篇同系列却互不链接——这是真缺口，补内部互链成本极低、收益明显 |
| **单点技术笔记**（GPU infra、MCP OAuth、continuous batching） | 孤立深读 | ⚠️ **值得补**。它们与长上下文/推理效率块有天然关联，只是当时没写交叉引用 |
| **本周新笔记**（视频生成调研） | 刚写完 | ⏳ 正常，还没有后续笔记引用它 |

**我的结论**：41% 孤立率**不是问题**，因为大部分是设计上的素材层。真正值得动手的只有两处——**LLM 入门 8 篇的内部互链**、以及**几篇单点技术笔记向效率块补链**。

## 5. 这套方法给我的三条实操结论

1. **"写的时候就串联" 有效且被量化验证**。社区 #7 和第 2 名意外连接都是手写交叉引用的产物，权重比文献重叠更高。→ 继续保持。
2. **素材层与综述层要分开看**。用 degree 衡量所有笔记是不公平的——digest 的价值在于被消费。→ 未来若要改进脚本，可给 digest 类型单独设阈值。
3. **桥节点要优先维护**。3 篇承重笔记（尤其长程 agent 整理）一旦过时，多个知识块同时受影响。

## 复现

```bash
# 生成洞察报告 + 交互图数据（会写 weekly/knowledge-graph.md 与 assets/knowledge-graph.json）
uv run --with networkx python3 scripts/wiki_graph.py
bash journal.sh index
```

图谱是**快照**：新增笔记后重跑即可刷新。本文解读基于 2026-07-30 的 104 节点快照。
