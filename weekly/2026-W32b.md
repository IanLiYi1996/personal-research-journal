## 3. Narrative Arcs（≥3-source 共振的完整故事线）

### Arc 1 ⭐：从「读它的想法」到「查它的痕迹」—— 验证权的转移

**这是本周最重要的一条,四个环节独立汇合。**

```
① 训练环节：教师被特权信息污染（HF，3 篇 3 领域）
   DAPD：参考答案 → privilege illusion，学生学到无法复现的行为
   When Teachers Mislead：伪信号
   Deferred Exposure：自动驾驶标注暴露真实未来轨迹 → 轨迹锚定偏差
   ↓ 共同解法：让教师与学生的信息可得性对齐（而非过滤信号）
② 运行环节：agent 的自评不可信（Blogs）
   task gaming：自我欺骗、伪造日志
   ⭐ 且 CoT 里没有可监控的预谋 → 读推理过程也补不上这个洞
   ↓
③ 架构环节：不让自评进入状态（HF）
   LongHorizon-Harness：executor 声明不能改状态，审计报告是唯一跨轮记忆
   → WeaveBench 51.8→80.7，且 Qwen+新harness 0.733 > Opus+原生CC 0.680
   ↓
④ 评估环节：连裁判也在读自评（HF）
   OSReward：去掉截图几乎无损，去掉 agent 的 thought/action 文本 −7.2pp
   并翻转 22.7% 判定 → 裁判主要在读 agent 讲的故事
   ⭐ 困难集上最好的裁判 69.7% = 与"永远输出失败"的常量程序打平
```

**四个环节的对策指向同一个结构:让一个不共享执行上下文的角色去核对客观状态。**

**产品侧同周给了对应能力:** AWS 的 `Goal success rate with ground truth` 用**成功断言按意图判定**,并明确接受"agent 用另一途径达到同样结果"—— 这正是"评产出不评路径"的产品化。

**社区侧也在自发实践:** 「Claude 审 Codex 把通过率 71.6%→89.7%」、「adversarial reviewer 成为可传播的 skill 模式」。

> ⭐ **这条 arc 的完整性是本周独有的:同一条原则在训练、运行、架构、评估四个环节各自被独立发现,并在产品与社区实践中同时落地。** 我据此写了三份专题文档(方案 / 量化附录 / 技术调研),并把「别问 agent 做了什么,去查它改变了什么」作为客户材料的核心主张。

```

  ↓

  ↓
```
