## Top Highlights

- [Amazon SageMaker AI inference now supports G7 instances](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-sagemaker-ai-g7/) — **High**。G7 由 **NVIDIA RTX PRO 4500 Blackwell Server Edition** 驱动，官方口径比上代 G6 有 **最高 4.6× 推理性能**。规格上是 **每 GPU 32GB 显存 + 第 5 代 Tensor Core + 最高 700 Gbps EFA 网络（G6 的 7×）+ 最高 7.6TB 本地 NVMe**。AWS 罕见地把适用区间写死：**7B–30B 参数模型**、图像/视频类负载。痛点陈述也直白 —— 此前部署这一档模型只有两条路：over-provision 贵算力，或量化模型硬塞进显存。**700 Gbps EFA + 7.6TB 本地 NVMe 的组合意味着这不只是"便宜一点的 GPU"**：大权重可以贴着算力放，冷启动/换模型的代价显著下降，对多模型托管（MME）类场景影响大于单纯的 TFLOPS 提升。
- [Amazon RDS for SQL Server now supports Microsoft SQL Server 2025](https://aws.amazon.com/about-aws/whats-new/2026/07/rds-sqlserver-supports-sqlserver-2025) — **High**。支持 Enterprise / Standard / Developer 三个版本。真正的架构含义是 SQL Server 2025 **把 AI 集成做进了数据库引擎**：可从 **T-SQL 直接调用外部 REST 端点，不需额外中间件**。AWS 点明的用法是让存量数据库负载直接接 **Amazon Bedrock、SageMaker、S3、Lambda**，且**无需重构应用** —— 场景举例为 AI 驱动的查询顾问、自动化性能分析、事件驱动工作流。另外两点值得注意：新增**免费的 Standard Developer Edition（Dev-SE）**用于开发测试（省许可费），以及 Standard Edition 容量上限提升。
- [AWS Secrets Manager now publishes secret update notifications to Amazon EventBridge](https://aws.amazon.com/about-aws/whats-new/2026/07/secrets-manager-update-notifications) — **High**。此前要知道密钥值变了，只能**把 CloudTrail 事件解析进 EventBridge，还得自己匹配 rotation success / PutSecretValue / UpdateSecretValue 多个 API 事件**——脆且容易漏。现在 Secrets Manager 直接向 EventBridge 发事件，用规则检测「active secret value 变化」（如轮转期间）并路由到 Lambda / SNS / SQS / Step Functions。**直接后果：缓存凭证的主动刷新终于有了可靠触发点**，不必再靠 TTL 猜或靠连接失败重试兜底 —— 轮转期间的凭证窗口问题是这类系统最常见的间歇性故障源。
- [Amazon EKS now supports AWS PrivateLink for the cluster OIDC endpoint](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-eks-oidc-endpoint-privatelink) — **High**。每个 EKS 集群会在 OIDC 端点公开签名公钥供 **IRSA**（IAM roles for service accounts）使用，此前访问这个端点**需要出网**。现在可创建 `com.amazonaws.<region>.oidc-eks` 接口 VPC 端点，让 VPC 内的 eksctl / Terraform / 自定义 token 校验器**私网**取 OIDC discovery 文档与 JWKS。这解掉的是**无出网 VPC 里 IRSA 装不起来**的老问题（也顺带修正启用 EKS 管理 VPC 端点 + private DNS 时的 DNS 解析），且**除标准 PrivateLink 费用外不额外收费**。
- [AWS HealthLake identifies and links duplicate patient, provider, and organization records (Preview)](https://aws.amazon.com/about-aws/whats-new/2026/07/aws-healthlake/) — **High（Preview）**。新增 **resource matching**，在 datastore 内自动识别并链接重复记录，覆盖 **7 类 FHIR 资源**：Patient、Practitioner、Organization、Location、Device、RelatedPerson、PractitionerRole。匹配依据是高置信度医疗标识符（SSN、病历号 MRN、国家提供者编号 NPI 等）。公告开头的问题陈述很实在：重复患者记录导致信息散落 → 重复检查、漏诊、计费错误、人工对账，以及**分析时把一个患者数成多个**。定位是**不必上专门的 MDM（主数据管理）工具**就能建可信的纵向患者记录。
