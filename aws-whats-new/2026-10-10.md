### 内容

- **Bedrock 给 OpenAI 模型开放 `reasoning.summary`（Responses API）** —— 返回的是「模型推理的人类可读摘要」而不是原始 CoT。放进我的监控主线看，它恰是 Pachocki 09-06 那篇说的设计（刻意隐藏原始 CoT 以保护它不受监督压力）在产品层的对应物：开发者拿到的是**模型自己写的、关于自己推理的二次叙述**，按 Runtime Contract 的分法属软证据，与「不能信自我报告」是同一张桌子。公告把用途写成「评估响应、调试、向用户展示模型如何处理请求」—— 前两个用途正是最该追问「摘要与实际推理是否一致」的地方，而这一点在 OpenAI 自己的 CoT 可监控性文献里是开放问题。全部 OpenAI 模型、全部已上线区域、含 in-Region / GEO / global 三种推理 profile。
- **TwelveLabs Pegasus 1.5 上 Bedrock**（第三方视频→文本模型，整段视频一次读、输出带时间戳的结构化事件，「不需要预先索引或摄取管线」）—— 走 US / Global 跨区域 profile。补录接住（延迟 3.6–27.5h）。
- **SageMaker Unified Studio 自定义 Tooling blueprints**：管理员用自己的 CloudFormation 模板定义项目环境（公司命名规范的 IAM role、自定义 permissions boundary 替代 AWS 托管策略），**服务在注册时校验一次、每次项目部署后再校验一次，确认所需资源存在后才让团队成员使用** ⟹「写入前设闸门」在数据平台项目环境上的形态，且闸门对象是权限边界 —— 落在「谁授权了这个动作」主线。
- **GuardDuty RDS Protection 检测 Aurora / RDS 里的数据外泄与破坏** —— 我追的 agent 破坏事故（Fable 5 删 220 万文件 / Replit 删库 / 邮件 agent 删 200 多封邮件）全在「执行前拦」那一侧有对策，这条是**事后检测**那一侧第一次在数据库层出现具名产品能力；它不替代闸门（破坏已发生），但补上了 Runtime Contract 证据面里「验证器只读外部状态」的一个现成来源。impact 启发式给了 Medium，我认为偏低。
- **Lambda 自管 Kafka ESM 支持 OAuth**（含 Confluent Cloud / Aiven / Redpanda）：此前只有 SASL/PLAIN、SCRAM、mTLS，公告明说受监管行业因为要求 OAuth 而用不了 ⟹ 身份层接企业 IdP 的又一处补齐。
- **Security Hub 导出 findings 到 S3（CSV 或 OCSF JSON）**，用途写的是 compliance reporting 与 audit evidence ⟹ 审计证据的产物化，与 09-30 Private CA 签发日志、10-09 OpenSearch advisory acknowledgment 写进模板同族。
- **Connect Customer 给绩效评估表做自动检查**：对「由 AI 自动填写的评估」，一键比对最佳实践，列出**哪些评估问题缺少足以让 AI 可靠打分的上下文**并建议改具体（例：「坐席是否做了销售披露」要先定义必须披露什么），且明说要「公平准确地给人类坐席与 AI 坐席打分」⟹ 这是「评估者本身需要被评估」主线在联络中心产品里的实现，而且它改的是**评分标准的可操作性**而不是评分器。⚠️ 它按 `NO_CATEGORY` 钉在 其他 ＝「最接主线却落兜底类」第四条（09-24 Connect A2A · 09-26 MCP skills · 10-01 Marketplace metering · 今天），退出条件不变。
- **Quick 品牌模板**：从 PPT/Word 模板抽取颜色、字体、版式与规则，**品牌经理在发布前审阅并编辑抽取结果**；生成时若请求违反规则，Quick 解释原因并给合规替代 ⟹ 「抽取的规则要先经人审再生效」＋「拒绝时带解释」两个姿态，都是我在闸门设计里反复记的。
- **Claude Sonnet 5.5 / Opus 5.5 上 Kiro（GovCloud）**：Kiro 自报 Opus 5.5 比 Opus 5「工具调用少约 40%、token 约一半」，credit multiplier 2.2× → 2.0×；Sonnet 5.5 输出快 30%+。都是厂商内部基准、无第三方。⚠️ URL 路径写 `2026/06/`，落后四个月。
